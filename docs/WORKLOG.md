이 파일 하나로 사람, Claude, Codex(Astra)가 같은 현황을 본다. 작업을 시작하기 전에 읽고, 끝나면 "작업 이력"에 한 줄 덧붙인다. 기획의 근거와 숫자는 `docs/PLAN_DB_PROGRAM.md`, 자료 점검은 `docs/research/`에 있다.

## 1. 프로젝트

- 목적: 초등 저학년 남매가 학원에서 매주 받는 영어 원서(Geronimo Stilton 수준)를 읽는 데 필요한 어휘를 빠르게, 가능한 한 많이 보게 하는 iPad 게임. 기본 형태는 플래시카드이고, 재미는 게임을 그 위에 얹어서 만든다.
- 단어 자료: `reference/weekly-tool/vocabulary.json` (카드 6,591장, 표제어 4,671개. 읽기 전용). 학습 대상은 P1 1,215 / P2 2,310 / P3 1,085.
- 사용자: 부모(전략 업무 종사자). 한국어로 소통, 영어 용어는 원어 유지. 결론부터 쓰고 근거에는 [verified] [recall] [estimate]를 표시한다.

## 3. 바꿀 수 없는 조건

- 답을 먼저 보여 주지 않는다. 카드는 단어와 소리가 먼저이고, 뜻은 아이가 "알아요/몰라요"나 보기를 고른 뒤에 공개한다.
- 소리가 먼저 나와도 된다(사용자 결정). 음성 실패 시 카드를 유지하고 다시 듣기를 준다. 소리 없이 완료 처리하지 않는다(부모 확인용 우회는 `소리 없이 계속`으로 기록).
- 복습은 1·3·7·14·30일. 같은 카드는 하루 한 번만 채점. 7일 이후 복습은 항상 확인 카드.
- 남매 기록은 분리한다. 점수 비교 화면은 만들지 않는다(두 아이 합산 협동 목표는 가능).
- 어떤 보상(별, 아이템, 열쇠, 게이지)도 복습 일정과 카드 등급을 바꾸지 않는다.
- 합성 음원을 "사람이 검수함"으로 표시하지 않는다. `reference/` 원본 파일은 고치지 않는다.
- 유료 크레딧 도구(Firecrawl 등)는 사용자 승인 없이 쓰지 않는다. 하위 에이전트에도 같은 제한을 둔다.
- 파일 4개 이상을 건드리는 변경은 3~5줄 계획을 먼저 사용자에게 보인다. 파일 삭제, 기록 재작성, 인증정보는 먼저 확인한다.
- 폐기된 제약: 하루 15분 상한과 하루 새 단어 상한은 `cards/`에 두지 않는다(사용자 결정 2026-11-12).

## 7. Astra 지시서: 세계관과 스테이지 설계

목표: DB 전체 4,610개 단어를 덮는 지도를 구성한다. 대륙마다, 세계마다 서로 다른 컨셉트가 있고, 모두가 하나로 이어지는 이야기가 있다. 먼저 사용자에게 보일 설계 문서와 데이터 형식을 낸다. 구현(생성기)은 승인 뒤에 한다.

읽을 것: 이 문서 1~3절, `docs/PLAN_DB_PROGRAM.md`의 9절(게임 요소), 17절(지도·보상), 18절(전체 구성). `cards/data/words.json`의 `world`가 현재 시제품의 세계 1개 형식이고, `cards/js/map.js`가 지도 규칙이다.

구조 (PLAN 18절, 필요하면 근거를 대고 바꿀 수 있다)
- 대륙 3개: P1 1,215 / P2 2,310 / P3 1,085 단어(대역 순서 고정). 세계는 대륙 안에서 약 150단어씩, 합쳐 약 30개(P1 8, P2 15, P3 7 추정).
- 세계 안 (사용자 연결 보완 요청 반영): 큰길과 긴 우회로가 중간에서 다시 만난다. 경로별 거리·카드 수를 같게 맞추지 않으며 긴 길에는 선택 놀이집을 둔다. 완료 칸은 무료로 되짚고 남긴 칸에 접근한다. 성은 도달로 열며, 전체 왕관은 모든 칸·필수 집·성 완료가 필요하다. 보너스 집·선택 몬스터·박쥐 게이지는 공통이다.
- 단어 배정은 빈도 순서가 정한다(어린이 글 빈도 → 일반 빈도 → Cambridge 단계 → 근거 없는 단어). 세계관은 단어 의미와 이어질 필요가 없다(사용자 결정). 즉 세계 컨셉트는 화면과 이야기의 "옷"이다.

문서에 담을 것 (`docs/WORLD_BIBLE.md`)
1. 전체 줄거리: 아이 둘이 함께 쓰는 이야기. 발단, 대륙 3개를 지나는 흐름, 결말. 두 아이가 같은 이야기를 공유하고 점수는 비교하지 않는다.
2. 대륙별 컨셉트와 이야기 역할.
3. 세계별 카드(약 30개): 이름, 한두 줄 컨셉트, 색 3개(하늘, 땅, 길의 16진 색), 길 이름·아이콘(이모지), 보스 이모지 6개 이상, 성(이름·이모지), 열쇠(이름·이모지), 입장 문구와 클리어 문구(각 두 문장 이내), 다음 세계로 이어지는 이야기 한 줄.
4. 대륙 끝 이벤트(큰 시험인 "대륙 성"과 연결).
5. 세계 데이터 형식과 예시(7절 아래 "접점").

제약
- 읽는 사람은 초등 저학년이다. 한 화면의 한국어는 짧은 두 문장 이내, 어려운 한자어 피하기.
- 화면 재료는 색, 픽셀 글꼴(Galmuri11), 이모지뿐이다. 새로 그리는 그림은 없다. 이모지는 오래된 iPadOS에서도 보이는 흔한 것으로 고르고, 세계마다 겹치지 않게 한다.
- 이야기 글에 목표 영어 단어와 그 한글 뜻을 짝으로 쓰지 않는다(정답이 미리 보이면 안 된다).
- 책 이름이나 등장인물(Geronimo Stilton 등)을 그대로 쓰지 않는다. 분위기(유령의 집, 탐정, 모험, 쥐)만 참고한다.
- 폭력, 공포가 강한 표현은 쓰지 않는다. 박쥐 게이지와 몬스터는 이미 있는 요소이므로 이야기에 자연스럽게 넣는다.
- 모든 세계가 같은 규칙으로 움직여야 한다(칸 10단어, 성, 보너스 집). 세계마다 규칙이 달라지는 새 기믹이 필요하면 먼저 제안만 하고 구현하지 않는다.

접점: 세계 데이터 형식 (제안. 바꾸면 이 문서 4절에 기록하고 Claude에게 알린다)
- v3: 최상위 `continents[]` → `worlds[]` → `map.nodes[]`, `map.edges[]`. 각 칸은 `words: [card_id...]`(DB의 `card_id`). 세계 필드: `id, name, concept, palette{sky,ground,path}, bossEmoji[], castle{name,emoji}, key{name,emoji}, intro, outro, story`. 장소 표시는 `routes[{id,name,icon}]`, 이동은 명시적 그래프, 성은 reach 조건. 대륙 필드: `id, band(P1|P2|P3), name, story, finale`.
- v1은 `castleNeeds`와 `roads[].tiles`를 사용하지만 연결망은 비호환이므로 schemaVersion=3로 전환한다. id/title 같은 표시값은 유지하고 새 로더가 필요함을 명시한다. 기존 시제품을 묵시 변환하지 않는다.

끝나면: 설계 문서와 형식을 `codex/` 브랜치로 올리고 이 문서 8절에 한 줄 적는다. 사용자 승인 전에는 생성기와 `cards/js/`를 건드리지 않는다.
