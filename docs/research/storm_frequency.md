# 실제 지도에서 회오리 빈도 측정 (C-008)

기준 커밋: `b44e85a98c445dced38b3ce576768c4c3809781b`.

## 가정과 해석

- 이것은 관찰된 아이의 예측이 아니라 **이상화한 시나리오**다. 실제 `worlds.json`과 `forms.json` 및 게임의 규칙 함수를 썼지만, 아이의 학습·오답·속도를 재현하는 학습 시뮬레이터는 아니다.
- 처음부터 매일 플레이하며 세계 파일에 나온 순서대로, 각 세계의 지도 학습 칸을 배열 순서대로 한 판에 하나씩 끝낸다. 실제 `reach`로 이 순서의 471칸이 모두 열려 있음을 별도 확인했다. 각 칸의 단어는 그 판에서 전부 만났고 이미 숙달한 `st: done` 기록이라고 가정한다. `startTile`, `settleWorld`, `unitDone`으로 칸을 끝내고 배달부 위치를 갱신한 다음 `stormTick`을 호출한다. 이 가정은 단어 복습 부채와 박쥐 게이지가 없음을 뜻한다. 박쥐·몬스터·복습·성·놀이 판과 관문은 시뮬레이션하지 않는다. 해당 판과 실제 오답·복습은 결과를 바꿀 수 있다.
- 지도 학습 칸은 471개, 중복을 뺀 단어는 4,489개다. 이 자료의 기본 학습 경로에는 집 칸이 없다. 나머지 목록 단어는 학습 경로에서 제외된 기능어다. 세계·대륙 성 통과도 별도로 가정한다.
- 하루 6·12·20은 **칸 판만** 센다. 회오리 판은 이 개수에 더해 즉시 수행한다. 아이가 회오리를 먼저 누르지 않고, 배달부와 회오리가 같은 칸이 되어 실제 `stormBlocks`가 참이면 그때만 회오리 판을 한다. 배달부가 회오리 칸으로 이동하는 경우도 포함한다. 판을 끝까지 풀고 모든 카드에 첫 답을 맞힌다. `StormRun`과 `settleStorm`이 실제 형태 기록과 종료를 처리한다.
- 형태는 서로 다른 날 두 번 맞히면 끝나고 같은 날 맞힌 것은 그날 다시 나오지 않는다. 따라서 유한한 형태 풀이 소진되면 이후 빈도가 떨어진다. 새 세계 판에서 이전 세계 회오리가 사라질 수 있고, 마지막 칸 뒤 남은 회오리는 추격을 계속하지 않는다.
- 난수는 게임의 `mulberry32` 씨앗 1~200을 각 설정에 사용한다. 게임 설정은 `on: true`, `cards: 5`, `need: 5`, `perDay: 3`, `doneAt: 2`; `chance`만 실행 중 0.20·0.35·0.50으로 바꾸고 `finally`에서 복구한다. 같은 씨앗의 설정 간 실행도 난수 소비 순서가 달라질 수 있다.
- 속도를 위해 완료 단어 기록은 실행 중 `words` 객체의 프로토타입에 둔다. 실제 규칙의 개별 ID 조회로는 모두 보이고 `unitDone`도 참이나, 열거와 직렬화에는 나타나지 않는다. 이 실험에서는 전부 `st: done`이어서 열거하는 박쥐 부채 계산에 기여하지 않는다. `STORM_VERIFY=1 STORM_SEEDS=1 node tools/measure_storm.mjs`로 보통의 열거 가능한 단어 기록과 아홉 설정 전체의 사건·카드 집계가 정확히 일치함을 확인했다. 이 임시 상태는 저장하지 않는다.

## 지도 거리와 최초 형태

아래 누적 형태는 별도의 정적 계산이다. 앞 세계부터 해당 세계의 마지막 지도 칸까지 모든 단어에 기록이 생겼다고 놓고, 회오리 판을 한 적이 없을 때 실제 `formPool`의 크기를 센다. 따라서 시뮬레이션 중 남아 있는 형태 수와 다르다. **처음 5개가 되는 곳은 p1-01 / p1-01-main-1(5개)**다.

거리 열은 각 배달부 위치에서 실제 `stormTick`으로 가장 먼 생성 칸을 고른 뒤 실제 `distances`로 잰 길 거리의 최소·중앙·최대다. 생성 칸이 여럿이면 난수 0으로 한 곳을 고르지만 거리는 같다. 첫 열의 위치는 시작점과 학습 칸, 둘째는 광장·성 등을 포함한 전체 지도 노드다. 짝수 중앙값은 가운데 둘의 평균이다. 출현 판 자체를 제외하고 배달부가 제자리에 계속 서 있으면 이 거리만큼 이후 판이 걸린다. 실제로 배달부는 매 칸 이동하므로 이 정적 거리는 움직이는 아이가 잡히기까지의 실제 판 수가 아니다.

## 일평균 사건과 카드

각 행은 씨앗 200개에서 사건 총수를 합하고 `200 × 플레이 일수`로 나눈 값이다. 471칸을 하루 6·12·20개씩 깨므로 각각 79·40·24일이며 마지막 일부만 플레이한 날도 하루로 센다. 30세계의 마지막 칸 뒤 활동은 넣지 않는다. 생성은 `spawn` 사건 수, 잡힘은 실제 `stormBlocks`가 참이 되어 즉시 처리한 횟수다. 카드 수는 완주한 `StormRun`의 `stats.cards` 합으로, 이 시나리오에서는 전부 첫 답이 정답이다. 이동 소멸은 `stormTick`의 `gone`, 풀 부족 소멸은 지도 표시 전 `stormRelease`가 제거한 횟수, 종료 시 남음은 마지막 칸 후 활성 회오리 수다. 각 씨앗에서 생성 = 잡힘 + 이동 소멸 + 풀 부족 소멸 + 종료 시 남음을 검사한다. 값은 소수 넷째 자리에서 반올림해 셋째 자리까지 표시하여 행의 합이 마지막 자릿수에서 다를 수 있다.
