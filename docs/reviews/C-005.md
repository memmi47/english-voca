# C-005 기록 보호·복습 규칙 교차 검토

검토자: Codex Astra. 날짜: 2026-11-16. 대상: `8ee40b41b3d46c6799ca77ad241911f94de8f65f` (`claude/modest-mccarthy-3gadjk`). 아래 줄 번호는 이 커밋 기준이다. 코드·테스트·저장 자료는 변경하지 않았다.

판정: **검토 완료, 실사용 전 수정 필요.** 기존 단위 58/58·브라우저 115/115는 통과하지만, 별도 재현에서 기록 손실·백업 보장 결함 4건, 복습 진입 불가 1건, 규칙 위반 3건을 확인했다. 비공개 백업 검증 누락 1건은 코드 판독 결과다. 특히 오래 열린 탭의 새 형식 덮어쓰기(F1), 접힌 판 병합 손실(F2), 중단한 칸의 다음 칸 열림(F7)을 우선 고칠 필요가 있다. 다음 구현은 Claude 카드로 넘긴다.

## 1. 발견 사항 — 심각도 순

### F1. 기록 손실 — 오래 열린 탭이 같은 브라우저의 새 형식 기록을 덮어쓴다

- **실제 재현: Chromium, 같은 context의 두 탭.** 서버 동기화를 끄고(`?set=demo&nosync=1&sound=off&fast=1`) 탭 A에서 아들 지도를 연다. 탭 B에서 같은 `cards.v0.p.son` 기록에 `v:2`, `futureOnly`와 새 단어 `futureWord`를 추가해 저장한다. 다시 탭 A에서 A1을 시작한다.
- 결과: 저장 형식이 **2→1**, `futureOnly`와 `futureWord`가 사라졌다. A의 `readonly`는 `false`다. 새 프로그램을 별도로 실행한 것은 아니며, B가 새 형식 기록을 쓰는 동작을 저장소 입력으로 재현했다. 서버가 없는 동안 생긴 새 기록에는 서버의 거부 규칙도 도움이 되지 않는다.
- 근거: [`main.js:39–41`](../../cards/js/main.js#L39)은 메모리의 `G.readonly`만 검사하고 현재 저장소를 재검사하지 않는다. 읽기 전용 값은 [`main.js:159`](../../cards/js/main.js#L159)에서 지도를 열 때 정해진다. 판 시작의 [`main.js:234`](../../cards/js/main.js#L234)가 그대로 저장한다. `storage` 이벤트 처리도 없다. DATA_SAFETY 2절의 “업데이트 중 열려 있던 탭” 보호가 이 경로에서 성립하지 않는다.
- 고치는 방향: 매 저장 직전 현재 저장 형식·변경 여부를 검사하고, 다른 탭의 변경은 병합하거나 읽기 전용으로 전환한다. 새 형식 감지 시 메모리·서버 쓰기 모두 중단한다.

### F2. 기록 손실 — 접기 경계보다 이른 다른 기기의 오프라인 판을 버린다

- **실제 재현: `compact`·`mergeCards`·`totals` 호출.** A에 2026-11-10 00:00부터 1분 간격으로 501판을 만들고 접는다(201판 접기, `past.until=03:20`). B는 공통 100판 뒤 01:40:30에 A에 없는 `offline-other` 판을 한 번 끝낸 상태다. 두 기록을 합친다.
- 결과: 서로 다른 판의 합은 **502판**인데 `totals(mergeCards(A,B)).n`은 **501판**이다. B의 단어 기록은 별도로 합쳐질 수 있지만 그 판의 카드 수·시간·학습 통계는 잃는다.
- 근거: [`store.js:35–38`](../../cards/js/store.js#L35)은 시간 경계와 합계만 남긴다. [`sync.js:59–60`](../../cards/js/sync.js#L59)은 더 먼 `past` 하나를 고르고 그 경계 이전 판을 모두 버린다. 서로 다른 기기의 과거 판을 그 `past`가 이미 포함한다고 보장할 수 없다. D5는 같은 이력의 접힌/안 접힌 사본만 검사한다.
- 고치는 방향: 기기별 단조 증가 판 ID·집계 경계 등 포함 여부를 판별할 정보를 보존하고, 확인하지 못한 오프라인 판은 버리지 않는다.

### F3. 기록 손실 — 시작 시 동기화가 손상 원문을 보관 전에 덮어쓴다

- **실제 재현: 메모리 저장소와 서버 응답 대역으로 `Sync.init()` 호출.** 로컬 키를 `{"v":1,"words":{"localOnly":`처럼 깨진 JSON으로 두고, 서버는 읽을 수 있는 기록을 반환한다. 앱 시작 순서대로 먼저 동기화한다.
- 결과: 로컬 키는 서버 기록으로 교체되며 **`.damaged.` 사본은 0개**다. 서버 복구는 되지만 로컬에만 있던 내용을 조사·복구할 원문은 사라진다.
- 근거: [`main.js:112–115`](../../cards/js/main.js#L112)가 프로필의 `loadRecord`보다 먼저 동기화한다. [`sync.js:79`](../../cards/js/sync.js#L79)는 파싱 실패를 `null`로, [`sync.js:104`](../../cards/js/sync.js#L104)는 이를 기록 부재로 처리해 덮어쓴다. 보관 코드는 [`store.js:53–60`](../../cards/js/store.js#L53)에만 있다. 기존 브라우저 10e의 손상 재현은 동기화를 끈 화면이라 이 시작 경로를 검사하지 않는다.
- 고치는 방향: 동기화가 읽기 실패와 기록 부재를 구분하고, 원문 보관에 성공한 뒤 서버 복구를 진행한다.

### F4. 기록 손실 위험 — 외부 업로드가 계속 실패해도 두 번째 백업은 성공으로 표시한다

- **실제 재현: Linux의 임시 git 저장소, 네트워크·실제 아동 자료 사용 없음.** 가짜 기록 하나를 만들고 백업 저장소의 `origin`을 존재하지 않는 로컬 경로로 설정한다. `CARDS_STATE_DIR=<임시 기록> bash tools/backup_state.sh <임시 저장소>`를 두 번 실행한다.
- 결과: 첫 실행은 로컬 커밋 뒤 push 실패로 종료 1, `offsite.ok=false`. 자료를 바꾸지 않고 재실행하면 push가 여전히 실패하지만 **종료 0, `offsite.ok=true`, `note="변경 없음"`**이 된다. 원격 저장소는 두 실행 모두 존재하지 않았다. 이 상태에서 Mac 디스크를 잃으면 외부 사본은 없다.
- 근거: [`backup_state.sh:42–44`](../../tools/backup_state.sh#L42)의 `git push ... || true`와 무조건 성공 기록. [`main.js:449–450`](../../cards/js/main.js#L449)은 그 값을 외부 백업의 정상 상태로 표시한다.
- 고치는 방향: 변경 없는 재시도도 push 성공 또는 원격의 해당 커밋 존재를 확인한 경우에만 성공 일자를 갱신한다.

### F6. 진행 막힘 — 모든 길·성을 마친 뒤 남은 소수의 재학습 단어를 다시 볼 수 없다

- **실제 재현: 체험판 전체 세계로 `worldView`·`nodeRun`·`finaleRun` 호출.** 모든 카드와 세계·대륙 성이 완료된 저장에 단어 3개만 `st:"learn", due:"2026-11-15", lastDay:"2026-11-14"`로 둔다. 박쥐는 `fill:0, cap:40, met:[]`, 오늘은 11월 16일이다. 마지막 시험에서 일부를 틀리고도 통과한 뒤 생길 수 있는 상태다.
- 결과: 밀린 학습은 3개지만 박쥐는 `full:false`; 모든 세계의 칸·집·성·몬스터·박쥐 및 대륙 성에서 **시작 가능한 학습 판 0개**다. 날짜만 지나도 3개가 40개가 되지 않는다. 장식 놀이는 복습 통로가 아니다. 같은 이유로 모두 완료한 뒤 남은 일반 복습 1~7개도 별도 진입 경로가 없다.
- 근거: [`map.js:27–31`](../../cards/js/map.js#L27)은 일반 due 수에서 `learn`을 제외한다. [`world.js:97`](../../cards/js/world.js#L97)은 몬스터에 복습 8개를 요구하고, [`world.js:113–120`](../../cards/js/world.js#L113)은 완료 칸·성을 다시 시작하지 않는다. [`deck.js:78,115`](../../cards/js/deck.js#L78)의 재시도 큐는 판을 시작할 수 있어야 동작한다.
- 고치는 방향: due/retry가 한 장이라도 남아 있으면 세계 진행·박쥐 한도와 무관한 복습 시작 경로를 제공한다.

### F5. 기록 보호 규칙 위반 — 게임 저장소 외의 공개 저장소는 백업 대상으로 거부하지 않는다

- **읽고 추론함; 공개 저장소 업로드는 실행하지 않음.** 사용자가 다른 공개 GitHub 저장소를 clone한 폴더를 백업 대상으로 주면 현재 검사상 통과한다. 저장 자료에는 아이 이름·학습 내용이 들어갈 수 있다.
- 근거: [`backup_state.sh:24–28`](../../tools/backup_state.sh#L24)은 `.git` 유무와 로컬 최상위 경로가 게임과 다른지만 확인한다. 이후 [`backup_state.sh:35–47`](../../tools/backup_state.sh#L35)은 파일 복사·commit·push를 한다. 원격 저장소의 공개 여부 검사는 없다. DATA_SAFETY 3절의 비공개 저장소 요구와 스크립트 주석의 보호 설명보다 실제 보장이 좁다.
- 고치는 방향: 업로드 전 실제 push 대상 저장소의 비공개 상태를 검증하고 확인할 수 없으면 업로드하지 않는다.

### F7. 규칙 위반 — 첫 만남 뒤 판을 중단해도 칸 완료와 다음 칸 열림을 만든다

- **실제 재현: 체험판 A1을 `Run`으로 실행.** 검증 추첨을 피하는 고정 난수 0.9로 첫 9단어는 알아요, 10번째는 몰라요를 답한다. 마지막 재학습 확인 1장이 남았을 때 `finish("quit")`와 `settleWorld`를 호출한다.
- 결과: `reason:"quit"`, 남은 카드 **1장**, `learn` **1개**인데 `cleared:true`; A2는 **`open`**이다. 새로고침만 해도 word 존재로 완료를 계산하므로 중단 판의 완료 표시를 따로 검사하는 것만으로는 부족하다.
- 근거: [`world.js:31,37,85`](../../cards/js/world.js#L31)은 단어 기록의 존재만으로 칸 완료·통과를 판단한다. [`world.js:139–142`](../../cards/js/world.js#L139)는 `rec.reason`을 검사하지 않는다. [`main.js:295–296`](../../cards/js/main.js#L295)은 답할 때마다 단어를 저장하고 [`main.js:319–321`](../../cards/js/main.js#L319)은 중단도 정산한다. WORLD_SCHEMA 4절 2번의 “판 중단 때 다음 지점으로 통과하지 않는다”와 충돌한다.
- 고치는 방향: 첫 학습 판 완료를 별도 조건으로 보존하고, 저장·재시작·BFS·왕관이 같은 완료 조건을 사용하게 한다. 이미 완료된 칸의 나중 복습 오답으로 길을 다시 잠그지는 않는다.

### F8. 규칙 위반 — 명시적으로 미정인 대륙 성 설정을 기본값으로 실행한다

- **실제 재현: 기준 커밋의 실제 `cards/data/worlds.json`.** 첫 대륙의 모든 단어·세계 성을 완료 상태로 만들고 `finaleRun`을 호출한다. 원본의 `finale`는 `cards:null`, `passRate:null`, `status:"pending-config"`다.
- 결과: 준비 중으로 막히지 않고 **40장·0.75** 판을 만든다. `settleWorld`에 그 판의 40/40 완료 결과를 주면 다음 대륙이 열린다. 왕관·시험 자체를 생략하는 버그라는 뜻은 아니다; 명시적 미정 설정을 승인된 설정처럼 취급하는 문제다.
- 근거: [`world.js:53,60–64`](../../cards/js/world.js#L53)의 null 병합 연산자와 상태 결정, [`world.js:124–128`](../../cards/js/world.js#L124)의 진입. WORLD_SCHEMA 2·8절은 null이면 준비 중으로 두고 다음 대륙을 열지 말라고 한다. 학습 부하 보고서의 40·75% 결정과 데이터 계약이 엇갈린 상태다.
- 고치는 방향: 누락된 구형 설정과 명시적 `pending-config`/null을 구분한다. C-001의 승인 수치 재생성은 현재 데이터 문제를 해소하지만 미정 입력의 런타임 처리도 맞춰야 한다.

### F9. 규칙 위반 — 같은 날 더 늦은 오답이 이전 정답과 병합될 때 사라진다

- **실제 재현: 두 저장에 같은 `firstDay`·`lastDay`를 주고 병합.** A는 그날 먼저 금(`done`, `due:null`)이 된 기록, B는 이후 성/박쥐 시험 오답으로 `learn`, 내일 due가 된 기록이다. `mergeCards(B,A)`를 호출한다.
- 결과: B의 **`learn`→`done`**, 내일 재학습 일정이 사라진다. 반대 인수 순서도 같은 결과다. 단어 수가 같아 서버 축소 거부도 검출하지 못한다.
- 근거: [`sync.js:12–15,57`](../../cards/js/sync.js#L12)은 일자와 진행 등급만 비교한다. [`deck.js:199–200`](../../cards/js/deck.js#L199)은 시험 오답을 실제로 `learn`으로 되돌린다. 로그 시간은 단어별 승자 결정에 쓰이지 않는다.
- 고치는 방향: 단어별 마지막 답의 시각/인과 버전을 저장하고 같은 날의 최신 오답도 보존한다. 저장 형식 변경 시 SCHEMA·STEPS·옛 저장 fixture 규칙을 따른다.

## 2. 여섯 검토 항목의 나머지 확인

| 카드 요구 | 확인과 한계 |
|---|---|
| ① 기록 손실·병합·거부 | F1~F4·F9 재현. 정상적인 오래된 형식 변환, 미래 서버 형식 거부, 동기화 충돌·오프라인 후 복구, 서버 축소/구형 저장 거부는 D1~D8·S1~S10 및 브라우저 10e·11 통과. 서버 주 기록은 flush/fsync 후 rename이며 프로세스 종료 중간 파일 노출은 줄이지만 전원 차단·디스크 손상 실험은 하지 않았다. 같은 단어 집합을 추가하는 정상 저장이 축소 규칙에 걸리는 사례는 발견하지 못했다. |
| ② DATA_SAFETY 약속 | F1~F5가 보호 범위의 빈틈이다. 기존 저장소 키·카드/세계 ID·fixture는 변경하지 않았다. 일자별 복원·다른 아이 파일 거부는 기존 검사 통과. |
| ③ 보상이 일정·등급 변경 | `map.settleRun`, `settleLightning`, `world.settleWorld`, `stampGame`은 단어 일정에 쓰지 않는다. 방패/불꽃은 combo·피해량·보스에만 영향을 주며 `_miss`의 일정 변경을 막지 않는다. M8·M9·W 놀이 검사 통과. 성/박쥐의 **오답**으로 일정이 바뀌는 것은 보상 효과와 구분했다. 회오리는 아직 구현 전(T-007/T-008)이므로 독립 일정 여부는 검증할 코드가 없다. |

## 3. 시뮬레이션 결론의 적용 한계

- **읽고 추론함; 이번 카드에서 시뮬레이션 전체를 다시 돌리지는 않았다.** `learning_load_sim.md:26–30`은 deck/map 실제 코드를 사용하지만 [`sim_learning.mjs:29–36,110–125`](../../tools/sim_learning.mjs#L29)는 세계 배정·진입·성 진행을 별도로 구현한다. 실제 v3 갈림길, 미완료 칸 재방문, 조기 세계 성, 집·놀이·중단 동작을 그대로 검증하는 회귀가 아니다. F6·F7 같은 UI 진입/완료 문제를 이 수치로 반증할 수 없다.
- 기준 아이의 S0=6.2, growth=2.6, 기존 지식 비율, 추측·실수·플레이 시간은 [`sim_learning.mjs:43–49,66–84`](../../tools/sim_learning.mjs#L43)의 가정이다. 정답 선택 확률에는 뜻을 기억하지 못한 추측 성공도 포함된다. 보고서의 “기억”은 실제 측정 점수가 아니라 잠재 회상 확률의 합이다. 기존 지식은 장기 망각 대신 고정 slip을 사용한다.
- 하루 15분은 [`sim_learning.mjs:104,117`](../../tools/sim_learning.mjs#L104)에서 **판 시작 전** 검사하고 판을 끝까지 돌리므로 마지막 판만큼 넘길 수 있다. 중단·피로·음원 실패·놀이 시간이 없다. “같은 시간”과 한 판 5분 이내 판단은 실제 세션 시간 기록으로 다시 확인해야 한다.
- 보고서 자체도 S0를 절반으로 하면 52주 만남 4,496→2,349, 기억 79%→약 62%, 박쥐 비중 30%→70%로 악화됨을 공개한다(`learning_load_sim.md:151–167`). 최근 복습 우선·75% 성 기준의 방향은 비교 가설로 쓸 수 있으나 두 아이의 첫 2주 정답률·실제 분량·박쥐 비중으로 재추정해야 한다. 소수 seed 평균에는 분산·신뢰구간이 없고 “영구히 막힌다”는 표현은 78주 유한 실험보다 강하다.
