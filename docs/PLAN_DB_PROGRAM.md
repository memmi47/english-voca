# 단어 DB 학습 프로그램 기획안

작성일 2026-11-11. 대상: 초등 저학년 남매, iPad, 하루 15분. 기존 `game/`(장면 탐험·탐정형)은 그대로 두고 별도 프로그램으로 새로 만든다는 전제다.

표기: [verified] 이번 작업에서 DB·코드·검색으로 확인. 웹 출처는 검색 결과 요약을 읽은 것이고 원문 전체를 열람하지는 않았다. [recall] 기억에 의존. [estimate] 계산·추정이며 방법을 함께 적는다.

## 0. 요약

- 지금까지의 구조는 "주간 팩 10~15개 + 팩마다 장면 그림"이다. 이 속도로는 DB의 모르는 단어 약 3,000개에 256주가 걸린다 [estimate, 8절]. 빠른 catch-up이라는 목적과 맞지 않는다.
- 새 프로그램은 DB 전체를 하나의 학습 대기열로 보고, 하루 15분에 인출 약 100회를 채우는 것을 중심에 둔다. 기준 시나리오에서 하루 새 단어 7.7개, P1 완료 14주, P1+P2 완료 52주, 전체 73주다 [estimate].
- 속도를 만드는 장치는 세 가지다. 아는 단어에 시간을 쓰지 않는 사전 확인, 책 읽기 기여도 순서의 대기열, 그림·이야기 제작이 필요 없는 카드 단위 자산(음성, 예문, 한글 뜻).
- DB에서 가장 큰 공백은 예문이다. 6,591장 중 45장에만 있다 [verified]. 음성 6,591장분과 함께 일괄 제작해야 하며, 비용은 돈보다 검수 시간이다.
- 흥미와 디자인은 문서로 확정할 수 없다. 단어 60개로 핵심 화면만 만든 시제품을 두 아이에게 3회 써 보게 하고, 그 결과로 계속 여부를 정하는 관문을 첫 단계에 둔다.

## 1. 문제 재정의

### 1.1 왜 양이 필요한가

- 읽기 이해에 필요한 아는 단어 비율은 최소 95%, 적정 98%로 본다 [verified: Laufer 계열·Hu & Nation 인용, 16절]. 단, 뚜렷한 문턱이 있다는 데는 반론이 있다(Schmitt 외 2011).
- Geronimo Stilton은 Lexile 410L~650L이고 확인한 권들은 대체로 8,000~10,000단어다(긴 권은 2만 단어 이상) [verified: 16절]. 10,000단어 책에서 95%는 모르는 단어 500회, 98%는 200회 등장을 뜻한다 [estimate: 10,000 × 5%, 2%].
- 어린이 글의 약 90%는 고빈도 약 874어(New Dolch List, 90%는 v1.0 875어 기준 수치)로 덮인다 [verified: 16절]. DB에는 이 중 856어가 있고 모두 P1이다 [verified: DB]. 즉 90%까지는 수백 단어로 가지만, 90%에서 95~98%로 가는 구간은 빈도가 낮은 수천 단어가 필요하다.
- 결론: 주 10~15개로는 P1을 마치는 데도 여러 해가 걸리고, 책의 미지어 비율은 거의 움직이지 않는다. 필요한 것은 하루 처리량이다.

### 1.2 전달 경로

빈도 분포(소수의 단어가 대부분의 등장을 차지) → 학습 순서가 책 기여도를 결정 → 하루 인출 횟수가 새 단어 수의 상한을 결정 → 새 단어 수가 미지어 비율의 하락 속도를 결정 → 쪽당 모르는 단어 수(기존 성과 지표)가 내려감.

## 3. 목표와 성공 기준

| 구분 | 기준 | 측정 |
|---|---|---|
| 1차 목표 | P1 1,215개를 "익힘" 상태로 | 프로그램 기록 |
| 2차 목표 | P1+P2 3,525개 | 프로그램 기록 |
| 최종 지표 | 실제 책에서 쪽당 모르는 단어 4주 내 3개 이하, 8주 내 2개 이하 (기존 주간 도구의 기준 유지) | 사전학습하지 않은 쪽을 부모가 주 1회 기록 |
| 과정 지표 | 분당 인출 7회 이상, 복습 정답률 80~90%, 주간 거부 1회 이하 | 프로그램 기록 + 부모 기록 |

"익힘"의 정의: 1·3·7·14·30일 복습을 연속 통과하고, 마지막(30일) 확인을 소리 도움 없이 처음 보는 문장에서 통과한 상태.

## 4. 설계 원칙

1. 인출이 진행이다. 세션 시간의 90% 이상이 문항에 쓰인다. 이야기·이동·연출은 문항 사이에 끼우지 않는다.
2. 아는 단어에 시간을 쓰지 않는다. 가르치기 전에 먼저 묻는다.
3. 순서는 책 읽기 기여도가 정한다. 주제 묶음이나 알파벳이 아니다.
4. 카드당 자산은 일괄 제작할 수 있는 것만 쓴다. 음성, 예문, 한글 뜻, 있으면 이모지. 직접 그리는 그림은 없다.
5. 재미는 속도, 연속 정답, 자기 기록, 눈에 보이는 누적에서 만든다.

## 5. 학습 모델: 단어 하나가 거치는 길

### 5.1 단계

| 단계 | 시점 | 하는 일 | 통과 시 | 실패 시 |
|---|---|---|---|---|
| 사전 확인 | 처음 만날 때 | 글자와 소리를 주고 뜻을 고른다. "몰라요" 버튼이 있다 | 빠른 정답이면 "아는 듯"으로 분류, 7일 뒤 재확인 | 소개로 이동 |
| 소개 | 사전 확인 직후 | 글자, 소리, 한글 뜻, 예문 1개를 약 12초 보여 준다 | - | - |
| 당일 인출 | 같은 세션 | 2문항 뒤, 5문항 뒤, 런이 끝날 무렵에 다시 묻는다 | 3회 중 마지막 정답이면 1일 뒤 복습 | 다음 날 새 단어로 다시 |
| 복습 1 | 1일, 3일 | 글자를 먼저 보고 뜻을 고른다. 소리는 답한 뒤 | 다음 간격 | 5.3의 규칙 |
| 복습 2 | 7일, 14일 | 예문 속에서 뜻 고르기 또는 빈칸 채우기 | 다음 간격 | 5.3의 규칙 |
| 최종 확인 | 30일 | 학습 때 보지 않은 새 문장에서 확인 | 익힘 | 5.3의 규칙 |

- 사전 확인의 근거: 답을 모른 채 먼저 시도해 보는 것이 이후 학습을 돕는다는 실험 결과가 있다 [verified: Kornell, Hays, Bjork 2009; Richland, Kornell, Kao 2009, 16절]. 실험 재료는 성인의 단어 쌍과 글이었고 어린이 어휘 학습에 그대로 옮겨진다는 근거는 확인하지 못했다. 이 설계에서 사전 확인의 주된 목적은 아는 단어를 1회 인출로 걸러내는 것이다.
- "아는 듯" 단어는 재확인 7일(소리 없이), 30일(문장 속) 두 번만 거친다. 한 번이라도 틀리면 소개로 간다.

### 5.2 문항 유형

| 유형 | 제시 | 답 | 재는 것 | 쓰는 단계 |
|---|---|---|---|---|
| A 뜻 고르기 | 글자 + 소리 | 한글 뜻 또는 그림 4개 + "몰라요" | 형태→뜻 | 사전 확인, 당일 |
| B 읽고 뜻 고르기 | 글자만 (소리는 답한 뒤) | 한글 뜻 4~6개 | 소리 도움 없는 읽기 | 복습 1 |
| C 단어 고르기 | 한글 뜻 또는 그림 | 영어 단어 4개 | 비슷한 철자 구별 | 당일, 복습 1 |
| D 문장 속 뜻 | 예문, 목표 단어 강조 | 한글 뜻 4개 | 문맥에서 뜻 접근 | 복습 2, 최종 |
| E 빈칸 | 목표 단어가 빠진 예문 | 영어 단어 3~4개 | 문맥으로 단어 고르기 | 복습 2 |
| F 번개 | 단어 + 뜻 한 쌍 | 맞다 / 아니다 | 속도. 익은 단어의 유지 | 세션 끝 1분 |
| G 철자 | 소리 + 뜻 | 글자 타일 | 철자 | 부모가 고른 단어만 |

- 4지선다는 찍어서 맞힐 확률이 25%다. 대응: "몰라요" 버튼, 복습 단계부터 보기 6개(17%), 같은 한글 뜻 712장과 발음이 같은 단어는 보기에서 서로 제외, 오답 보기는 같은 품사·비슷한 우선순위 대역에서 뽑는다.
- 기능어 121개는 한글 뜻이 없다. 뜻 문항이 아니라 "듣고 글자 고르기"만 하는 빨리 읽기 묶음으로 따로 돌린다.
- 한 묶음(새 단어 3~4개)에는 뜻이 비슷한 단어를 함께 넣지 않는다. 기존 요구(유사어는 처음에 따로 만난다)와 같다.

### 5.3 복습 규칙

- 간격은 요구대로 1·3·7·14·30일이다. 같은 카드는 하루 한 번만 채점한다.
- 틀렸을 때의 처리는 결정이 필요하다(12절 D4). 현재 규칙은 "처음으로 되돌림"이다. 한 단계만 내리면 필요한 복습 횟수가 줄어든다(8.3절).
- 하루 새 단어 수는 고정하지 않는다. 다음 날 만기 복습이 세션 용량을 넘을 것으로 계산되면 새 단어를 줄이고, 복습 정답률이 90%를 넘으면 늘린다. 범위 4~12개.

## 6. 하루 15분의 구성

| 구간 | 시간 | 내용 |
|---|---:|---|
| 시작 | 15초 | 소리 켜기 1탭 |
| 런 1 | 4분 30초 | 새 단어 묶음 1 (3~4개) + 만기 복습을 사이에 |
| 런 2 | 4분 30초 | 새 단어 묶음 2 + 만기 복습 |
| 런 3 | 4분 | 남은 복습, 문장 문항 위주 |
| 번개 | 1분 | 익은 단어 맞다/아니다, 자기 기록 표시 |
| 마무리 | 20초 | 오늘 익힌 단어, 지도 한 칸 채우기 |

- 런마다 10초짜리 결과 화면에서 멈출 수 있다. 한 번에 15분을 못 하는 날은 런 단위로 나눠 한다.
- 새 단어는 집중이 좋은 앞쪽에 두고, 복습은 새 단어의 당일 인출 사이를 벌려 주는 용도로 섞는다.
- 시간이 모자라면 잘리는 것은 런 3의 복습 꼬리와 번개다.

## 7. 학습 순서

대기열 순서는 아래 기준을 위에서부터 적용한다.

1. 이번 주 책 단어. 부모가 주간 도구에 책 표본을 등록하면 그 책의 모르는 단어가 맨 앞으로 온다. 하루 새 단어의 절반까지 차지한다.
2. 등록된 책들에서의 누적 등장 수(주간 도구의 corpus 값).
3. NDL 순위(어린이 글 기준, 856개).
4. NGSL 순위(2,024개).
5. Cambridge YLE 단계(Starters → Movers → Flyers).
6. P1 → P2 → P3.

- 빈도 근거가 없는 2,281개(P3 전부 포함)는 대역 안에서 주제를 돌려 가며 낸다. 공개 빈도 목록으로 순위를 보충하는 방법이 있으나 어떤 목록을 쓸지는 정하지 않았다.
- 1순위 뜻만 먼저 돈다. 2순위 이하 1,818장은 책에서 그 뜻이 등장했을 때, 또는 1순위 뜻을 익힌 뒤에 넣는다.
- 장르 단어 34개(ghost, rodent, whisker 등)는 Geronimo 계열에서 자주 나올 것으로 보고 P1 뒤에 바로 붙인다.

## 8. 처리량 시나리오

### 8.1 계산 방법 [estimate]

- 하루 순수 문항 시간 = 900초 - 전환·시작·마무리 90초 = 810초.
- 30일 간격에 도달하려면 복습 5회를 연속으로 맞혀야 한다. 정답률 p, 틀리면 처음으로 돌아갈 때 필요한 복습 횟수의 기댓값 = (p^-5 - 1) / (1 - p).
- 모르는 단어 1개의 비용 = 소개 12초 + (당일 4회 + 복습 기댓값) × 문항당 시간.
- 아는 단어 1개의 비용 = 3회 × 문항당 시간.
- 하루 새 단어 수 = 810초 ÷ 모르는 단어 1개의 비용.

### 8.2 시나리오

| | 약세 | 기준 | 강세 |
|---|---:|---:|---:|
| 문항당 시간 | 9.0초 | 7.5초 | 6.0초 |
| 복습 정답률 | 80% | 85% | 90% |
| 이미 아는 비율 P1 / P2 / P3 | 40 / 15 / 5% | 60 / 30 / 15% | 75 / 45 / 25% |
| 주당 학습일 | 5일 | 6일 | 6일 |
| 복습 횟수 기댓값 | 10.3회 | 8.4회 | 6.9회 |
| 모르는 단어 1개 비용 | 140초 | 105초 | 78초 |
| 하루 인출 횟수 | 90회 | 108회 | 135회 |
| 하루 새 단어 (모르는 것) | 5.8개 | 7.7개 | 10.4개 |
| P1 완료 | 28주 | 14주 | 8주 |
| P1+P2 완료 | 99주 | 52주 | 32주 |
| 전체(P3 보류분 제외 4,610개) 완료 | 135주 | 73주 | 46주 |
| 하루 20분일 때 전체 | 98주 | 53주 | 34주 |

- 비교: 주 12개 방식은 기준 시나리오의 모르는 단어 3,074개에 256주가 걸린다 (3,074 ÷ 12).
- 기준 시나리오 검산: 복습 기댓값 (0.85^-5 - 1) ÷ 0.15 = 8.36. 비용 12 + (4 + 8.36) × 7.5 = 104.7초. 810 ÷ 104.7 = 7.7개. P1은 모르는 486개 × 104.7초 + 아는 729개 × 22.5초 = 67,300초 = 83회 세션 = 14주.
- 문항당 시간, 정답률, 아는 비율은 모두 가정이다. 아이들에게서 잰 값이 없다. 14절의 첫 관문에서 실측해 이 표를 다시 계산한다.

### 8.3 지렛대

| 지렛대 | 효과 [estimate] | 비고 |
|---|---|---|
| 하루 15분 → 20분 | 전체 기간 약 27% 단축 (73주 → 53주) | 기존 요구는 15분 상한 |
| 오답 시 "처음으로" → "한 단계 아래로" | 복습 기댓값 8.4회 → 6.8회, 하루 새 단어 7.7 → 8.7개 | 기존 요구는 "실패 시 streak 0" |
| 문항당 1초 단축 | 하루 새 단어 약 +1개 | 화면 설계와 음성 길이로 좌우됨 |
| 아는 단어를 미리 걸러내는 정확도 | 아는 비율 10%p 차이마다 전체 기간 약 10% (단어당 비용 차이 82초 × 10% ÷ 평균 76초) | 사전 확인의 품질 |

## 9. 흥미와 디자인

### 9.1 무엇으로 계속하게 하는가

| 장치 | 내용 | 제작 비용 | 시간 비용 |
|---|---|---|---|
| 즉각 반응 | 정답 0.3초 효과음과 색, 오답은 정답을 바로 보여 주고 뒤에 다시 냄 | 효과음 3개 | 없음 |
| 연속 정답 | 연속 정답 수를 화면 위에 표시, 끊겨도 벌 없음 | 없음 | 없음 |
| 단어 지도 | DB 전체가 한 화면의 칸으로 보이고 익힌 단어마다 칸이 채워짐. 대역별 구역, 이번 주 책 구역 | 화면 1개 | 세션 끝 10초 |
| 책 미터 | "이 책 한 쪽에서 모르는 단어 예상 n개". 책 표본이 등록된 경우만 | 계산식 | 없음 |
| 번개 기록 | 1분 동안 맞힌 수의 자기 최고 기록. 남매 비교 없음 | 없음 | 1분 (복습을 겸함) |
| 가족 목표 | 두 아이 합산 주간 익힌 단어 수 → 부모가 정한 실제 보상 | 설정 1개 | 없음 |
| 출석 | 주 5일 달성 방식. 하루 빠져도 끊기지 않음 | 없음 | 없음 |

- 캐릭터·이야기·수집 요소는 1차 범위에 넣지 않는다. 시제품 시험에서 아이들이 3회 안에 지루해하면 그때 가장 싼 것(표정 4개짜리 캐릭터 1개)부터 더한다.
- 이 표가 실제로 흥미를 만든다는 근거는 없다. 가설이며 14절 첫 관문에서 확인한다.

### 9.2 화면 원칙

- 한 화면에 할 일 하나. 문항 화면에는 제시, 보기, 다시 듣기만 있다.
- 글자는 크게(목표 단어 56pt 이상), 보기는 손가락 폭 이상, 가로·세로 모두 스크롤 없이 한 화면.
- 답한 뒤 다음 문항까지 탭 없이 0.8초 뒤 자동 진행. 오답일 때만 "알겠어요" 탭을 받는다. 기존 화면은 매 문항 "다음"을 눌러야 해서 문항당 1~2초를 더 쓴다 [estimate].
- 발음 기호는 아이 화면에 넣지 않는다.
- 화면 수는 넷이다: 오늘(런 3개와 지도 요약), 문항, 런 결과, 지도·부모 현황.

## 10. 콘텐츠 제작과 비용

| 자산 | 수량 | 제작 방법 | 비용 | 검수 |
|---|---:|---|---|---|
| 단어 음성 | 서로 다른 형태 4,763개, 약 3.1만 자 | 신경망 TTS 일괄 생성 | 아래 참조 | 동형이의어 약 30개 형태와 자동 검사에서 걸린 것만 사람이 듣는다. 앱 안에 "발음 이상" 신고 버튼 |
| 예문 | 1순위 4,667개 (전체 6,591개) | 문장 생성 모델로 일괄 작성 | 출력 약 28만~40만 토큰 [estimate: 카드당 60토큰] | 자동 검사 + 5% 표본 사람 확인 + 신고 버튼 |
| 예문 음성 | 예문과 같은 수, 약 30만 자 [estimate: 문장당 45자] | TTS | 아래 참조 | 단어 음성과 같음 |
| 그림 | 이모지 323개 보유 | 이모지 대응만 확장. 새 그림 없음 | 0 | 뜻과 그림이 어긋나는 사례 점검 (fly, watch, ring, orange 등) |
| 한글 뜻 | 보유 | 정비만 (11절) | 0 | 부모 |

- TTS 비용: 전체 약 33만 자다. Google Cloud TTS는 Neural2가 100만 자당 16달러, Chirp 3 HD가 30달러이고 각각 월 100만 자까지 무료로 안내된다 [verified: 16절, 검색 요약 기준이며 구매 전 공식 가격표 재확인 필요]. 어느 쪽이든 10달러 이하 범위다 [estimate]. 제약은 돈이 아니라 발음 확인이다.
- 가족용이면 Mac의 `say`로 무료 생성도 가능하나 약관상 회색 지대가 있다(`docs/research/audio_ipad_research.md` 3.4절). 부모 녹음은 품질이 가장 확실하지만 9,000개 이상을 녹음해야 한다.
- 예문 자동 검사 항목: 목표 형태가 정확히 한 번 나오는가, 10단어 이하인가, 목표 단어 외의 단어가 모두 더 쉬운 대역(P1 또는 이미 익힌 단어)에 있는가, 그 카드의 뜻으로 쓰였는가. 앞의 세 가지는 DB만으로 기계 검사가 된다.
- 음성 자동 검사는 생성된 음성을 음성 인식으로 되돌려 원문과 비교하는 방식을 생각하고 있다. 실행해 본 적이 없어 걸러내는 비율은 모른다.
- 사람 검수 시간: 음성 약 20분(의심 200개 × 5초), 예문 약 40분(233개 × 10초) [estimate].
- 책 표본이 등록된 단어는 생성 예문 대신 실제 책 문장을 쓴다.

## 12. 기존 요구와의 관계

유지: 답을 먼저 보여 주지 않음, 음성 실패 시 문항 유지와 재시도, 남매 기록 분리와 점수 비교 금지, 복습 간격 1·3·7·14·30일, 합성 음원을 검수 완료로 표시하지 않음, 원본 파일 불변.

결정이 필요한 변경:

| 번호 | 사안 | 기존 | 제안 | 이유 |
|---|---|---|---|---|
| D1 | 학습 범위 | 주간 팩 10~15개 | DB 전체 대기열 + 이번 주 책 우선 | 1절 |
| D2 | 하루 시간 | 15분 상한 | 15분 유지. 20분은 선택지로만 | 8.3절 |
| D3 | 하루 새 단어 | 상한 8~10 | 정답률에 따라 4~12 자동 조절 | 기준 시나리오 7.7개는 기존 상한 안 |
| D4 | 오답 시 간격 | 처음으로 | 한 단계 아래로 | 8.3절. 복습 약 18% 절감 |
| D5 | 음원 | 사람이 검수한 음원에 의존 | TTS + 자동 검사 + 위험 항목만 사람 검수 | 9,000개 이상을 전부 듣는 것은 현실적이지 않음 |
| D6 | 소리 자동 재생 | 단어가 나올 때마다 | 복습 1단계부터는 답한 뒤에 재생 | 목표는 소리 없이 읽는 것. 소리가 먼저 나오면 읽기 실력을 잴 수 없음 |
| D7 | 장기 복습 대상 | 책 팩의 T1·T2만 | DB 대기열의 모든 단어. 책에만 나온 저빈도 단어는 노출만 | DB 카드의 99%는 티어가 비어 있음 |

## 13. 측정과 반증 조건

| 가설 | 반증 조건 | 반증되면 |
|---|---|---|
| 보기 고르기로 익힌 단어가 책 읽기로 옮겨 간다 | 프로그램에서 "익힘"인 단어를 책에서 막히는 일이 계속되거나, 4주 뒤 쪽당 모르는 단어가 줄지 않음 | 문장 문항과 소리 없는 문항의 비중을 올림. 그래도 안 되면 방식 재검토 |
| 어휘가 읽기의 병목이다 | 미지어는 줄었는데 이야기 질문 점수가 그대로 | 주간 도구 README의 분기(해독, 문장 길이)로 이동 |
| 아이들이 반복 문항을 2주 이상 계속한다 | 주 2회 이상 거부, 또는 분당 인출이 5회 아래로 | 새 단어 감축, 보상 장치 교체, 캐릭터 추가 순 |
| DB 순서가 Geronimo의 어휘와 맞는다 | 첫 책 표본에서 모르는 단어 중 DB P1·P2에 있는 비율이 70% 미만 | 책 단어의 대기열 비중을 올림 |
| 사전 확인이 아는 단어를 제대로 거른다 | "아는 듯" 단어의 7일 재확인 오답률 20% 이상 | 사전 확인을 2회로 늘림 |
