# 설계 결정 기록 (프로토타입 v0)

작성일 2026-11-11. 현재 요구의 기준은 착수 프롬프트와 `reference/weekly-tool/Game_Handoff.md`. 과거 벤치마크의 동물 수집 콘셉트와 전체 목록 승인 순서는 채택하지 않았다.

## 1. 게임 콘셉트 비교와 선택

판단 기준: 실제 독서 전이, 반복 동기, iPad 조작 부담, 음원·그림 제작 비용.

| 콘셉트 | 독서 전이 | 반복 동기 | iPad 조작 | 제작 비용 | 비고 |
|---|---|---|---|---|---|
| A. 장면 탐험 (한 장면에 8~10개, 소리→그림→문맥) | 높음. 책의 문장·쪽을 카드에 연결 | 중간. 불 켜기, 장면 복원 | 낮음 (탭만) | 중간. 장면당 그림 8~10개 | 선택 |
| B. 턴제 카드 수집 (Lingo Legend 유형) | 낮음. 수집이 어휘와 분리될 위험 | 높음 | 중간 | 높음. 카드·밸런스·캐릭터 | 반복 동기는 크나 비용이 크고 점수·수집이 기억 상태와 섞임 |
| C. 짧은 이야기 해결 (문맥 중심) | 높음. 문장 단위 | 중간 | 낮음 | 높음. 장면별 이야기 집필 | 구동사·추상어에 적합. A의 depth 3에 일부 흡수 |

선택은 A. 근거:
- 한 장면은 주간 팩 8~10개 단위와 맞고, 소리→그림·장면→문맥 순서를 한 화면 구조로 구현할 수 있다.
- 추상어는 그림 대신 문맥 문항으로 내려간다. 같은 틀에서 depth 1~4가 모두 작동한다.
- B의 반복 동기는 보상을 기억 상태와 분리해야 하는 위험이 있어 첫 버전에서 배제. 보상은 "혼자 맞힌 단어의 물건에 불이 켜짐" 하나로 한정하고, 일정에는 영향을 주지 않는다.
- 반증 조건: 2주 사용 후 아이가 장면 반복을 지루해하면 B의 수집 요소를 별도 선택 활동으로 추가 검토한다. 이것은 설계 가설이며 아이들에게 검증되지 않았다.

## 2. 한 세션의 흐름

(아래는 v0 퀴즈 화면 기준이다. 순서와 화면은 11절의 탐정형으로 바뀌었고, 문항 유형·오답 재도전·15분 규칙은 그대로다.)

소리 확인 → 복습(만기 T1/T2, 상한 25) → 새 단어 장면 학습(최대 5개/회, 설정 3~10) → 1라운드 depth 1 → 2라운드 depth 2 → 오답 카드의 간격 재도전 → 종료 화면(혼자 맞힌 단어, 내일 다시 볼 단어, 책에서 찾을 쪽).

- 새 카드는 학습 직후 depth 1(소리→그림, 그림 없으면 소리→뜻), 이어 depth 2(단어→뜻)에서 인출. 정답이 화면에 먼저 나타나지 않는다. 문장 빈칸(depth 3)에서는 문장 음성이 답을 말하므로 답한 뒤에만 재생한다.
- depth 3·4는 복습에서 한 단계씩 올린다 (`depthDone+1`, 상한 `min(depth_target, 티어 상한)`). T3는 2, T2는 3, T1은 4까지. 예문에 해당 단어가 없으면 depth 3으로 올리지 않고 낮은 depth로 대체한다.
- 오답이면 정답과 음성을 보여 주고, 같은 카드를 4문항 뒤 비채점 재도전으로 다시 낸다.
- 세션 15분: 화면이 보일 때만 시간이 흐르고, 같은 날 여러 번 해도 합산 15분. 종료 시점은 현재 문항이 끝난 뒤.

## 3. 채점과 복습 규칙

| 결과 | 기록 | 일정 효과 |
|---|---|---|
| 첫 시도 정답, 힌트 없음 (independent) | streak+1 | T1/T2: 1·3·7·14·30일. T3: 일정 없음 |
| 힌트 사용 후 정답 (hinted) | 별도 기록 | 가정: streak 유지, 다음 날 다시. 승급 없음 |
| 첫 시도 오답, depth 1~2 (wrong) | streak 0, 모름 | 다음 날 |
| 첫 시도 오답, depth 3~4이고 뜻은 이미 혼자 맞힌 카드 (wrong_step_up) | 앎·streak 유지 | 다음 날 뜻 수준으로 확인, 어려운 단계는 7일 뒤 재시도 |
| 오답 후 재도전 정답 (retry_success) | 별도 기록 | 일정에 영향 없음 |
| 소리 실패로 건너뜀 (skipped_no_audio) | 별도 기록 | 채점 안 함 |

- 같은 카드는 하루 1회만 채점. 만기 전 연습은 간격을 늘리지 않는다 (`core.py record_review`와 동일).
- 모든 게임 결과는 `assist: audio`로 기록한다. 종이 책에서 혼자 읽은 결과와 합치지 않는다. 진단 구간 추정 앎은 `inferred`로 따로 두고 일정을 만들지 않으며, 게임에서 틀리면 직접 오답으로 덮어쓴다.
- 읽기 지식(앎/모름, streak)은 depth 1~2에서 판정한다. 빈칸·철자를 틀렸다고 뜻을 아는 단어가 '모름'으로 바뀌면 성공 지표(쪽당 모르는 단어)와 주간 도구의 앎·모름 집계가 왜곡되기 때문이다.
- 힌트와 상위 단계 오답의 일정 처리는 요구 문서에 없는 가정이다. 바꾸려면 `srs.js`의 `applyScore`, `nextDepth` 두 곳이다.

## 4. 데이터와 저장

- 원본 `reference/weekly-tool/vocabulary.json`, XLSX는 수정하지 않는다. `tools/build_catalog.py`가 게임용 `game/data/catalog.json`(6,591 카드, 약 1.0MB)을 만든다.
- 팩은 주간 도구 `/export?profile=...` JSON을 그대로 읽는다 (`approved_packs`, `local_cards`, `card_states`, `reviewed_audio`). 데모 팩 두 개는 같은 형식이며 `_sample: true`로 표시된다.
- 저장은 두 겹이다. 작업 사본은 브라우저 localStorage(아이별 키 `catchup.v1.p.son` / `.daughter`, 공용 설정 키), 보관 사본은 Mac의 `tools/serve.py`가 `state/` 폴더에 쓰는 JSON이다.
  - 이유 1: WebKit 정책상 Safari는 7일간 상호작용이 없는 사이트의 localStorage를 지울 수 있다(홈 화면에 추가한 웹 앱은 예외). 8주 기록을 브라우저에만 둘 수 없다. 근거는 webkit.org/tracking-prevention, 검색 요약으로 확인했고 현재 iPadOS 동작은 실기기 미확인.
  - 이유 2: Mac과 iPad가 같은 진도를 본다.
  - 방식: 문서 3개(meta, p.son, p.daughter)를 버전 번호와 함께 저장. 다른 기기가 먼저 저장했으면 서버가 거부(409)하고, 클라이언트가 카드별로 더 최신 기록을 고르고 로그·세션은 합집합으로 병합한 뒤 다시 올린다. 서버는 원자적으로 쓰고 직전 30개 버전을 `state/backup/`에 남긴다.
  - 서버에 연결되지 않으면 기기에만 저장하고 첫 화면에 그 사실을 표시한다. 연결되면 밀린 기록을 올린다.
  - 한계: 한 아이가 두 기기에서 동시에 진행하는 경우는 병합으로 처리하지만 설계 대상이 아니다. 한 기기에서 지운 데모 데이터가 오래된 기기의 병합으로 되살아날 수 있다. 인증이 없으므로 가정 내 Wi-Fi 전용이다.
- 가져오기는 병합 전용이다. 팩 지문이 같으면 변경 없음, 다르면 tier·depth·context·page만 갱신하고 진도 필드는 건드리지 않는다. 다른 아이의 파일은 거부한다.
- 데모(sample)와 실제 팩이 같은 card_id를 쓸 때: 데모는 실제 레코드를 건드리지 않고, 실제 팩은 데모 레코드를 새 기록으로 대체한다. 학습만 하고 채점되지 않은 카드는 다음 세션에서 새 단어로 다시 나온다.
- 내보내기는 아이별 JSON. `card_states`는 주간 도구와 같은 `[known, origin, due, streak]` 순서이며 데모 카드는 제외한다.

## 5. 음성

- 공유 `<audio>` 1개를 "소리 켜고 시작" 탭에서 해제하고, 요청 토큰으로 오래된 재생을 취소하며, 같은 키 재생은 1.2초 안에서 중복 억제, 다시 듣기는 강제 재생. iOS 17+는 `navigator.audioSession.type='playback'`으로 무음 스위치를 통과시킨다. 근거와 한계는 `docs/research/audio_ipad_research.md`.
- 실패(차단, 로드 오류, 5초 타임아웃)는 배너와 다시 듣기를 띄우고 현재 문항을 유지한다. 소리에 의존하는 문항(소리→그림, 철자)은 복구 전까지 선택지를 잠근다. 부모용 "소리 없이 넘기기"는 채점하지 않는다.
- 음원 키는 card_id(뜻·시제별로 분리됨), 문장은 `card_id#s`. `audio/manifest.json`의 status: `dev_tts`(임시 합성), `candidate`, `human_approved`(사람 검수), `rejected`. 승인은 앱의 `#/review`에서 검수 로그를 내보내고 `tools/audio_tool.py apply-review`가 반영한다. 파일 해시가 바뀌면 승인이 해제된다. 어떤 도구도 스스로 `human_approved`를 만들지 않는다.
- 현재 음원 20개는 모두 ffmpeg flite(slt) 합성이며 `dev_tts`다. 발음 검증용이 아니다. 실제 음원은 부모 녹음, 또는 라이선스를 확인한 TTS로 교체한다. 라이선스는 조사 문서 3절, 소규모 세트의 제작·검수·교체 절차는 아래 6절.

## 6. 음원 제작·검수·교체 절차 (소규모 세트로 검증)

1. `tools/audio_sources.json`에 키·텍스트 정의 (목표 단어와 예문 별도).
2. 파일 준비: 개발용은 `python3 tools/audio_tool.py build`. 실제 음원은 같은 키 이름의 mp3/m4a를 `game/audio/reviewed/`에 넣고 매니페스트 항목 `file`/`sha256`을 갱신.
3. 앱 `#/review`에서 들어 보고 승인/반려, 로그 내보내기.
4. `python3 tools/audio_tool.py apply-review audio_review_log.json`. 해시 불일치는 거부.
5. 파일을 교체하면 승인은 `candidate`로 내려가 재검수가 필요.
전체 음원 일괄 생성 여부는 이 절차를 데모 20개로 한 번 돌린 결과(검수 시간, 수정 비율)를 보고 판단한다. 지금은 판단 근거가 없다.

## 7. 데이터 점검에서 나온 부모 검토 항목 (상세: docs/research/data_audit.md)

- starter 500의 첫 뜻 문제 (light=불을 붙이다, water=물을 주다 등), 같은 한글 뜻 25쌍, IPA 오류(use, lead, minute 등), 불규칙 과거형 84장 중 75장이 원형 뜻과 동일, image_type 오분류, depth 4 후보 21개가 부적절(be, do 등).
- 게임 반영: 동음 쌍(right/write)은 소리 기반 보기에서 서로 제외. 나머지는 데이터 수정 사항이라 건드리지 않았다.

## 8. 이번에 하지 않은 것

실제 책 표본 기반 팩, 말장난 코너, 월간 인쇄 연동, 듣기 진단(150문항), 전체 음원, 소리 도움 없는 읽기 확인 화면. 모두 근거 입력 또는 결정 대기.

## 9. 점검에서 바꾼 것 (2026-11-11, 2차)

코드 전체를 다시 읽고 5일치 세션을 실행해 확인한 결과다.

| 문제 | 영향 | 조치 |
|---|---|---|
| 진도가 브라우저 localStorage에만 있음 | Safari가 지우면 8주 기록 소실, Mac·iPad 비공유 | 서버 보관 사본과 병합 동기화 추가 (4절) |
| 세션 종료 시 "진행 중" 표시가 다시 붙음 | 같은 날 사용 시간 이중 계산, 다음 시작 때 유령 세션 기록 | 종료된 세션에는 표시를 쓰지 않도록 수정 |
| 빈칸·철자 오답이 단어를 '모름'으로 되돌림 | 읽기 지표와 앎·모름 집계 왜곡, 간격 초기화 | depth 3~4 오답은 읽기 지식을 유지 (3절) |
| 학습 화면에서 소리가 나기 전에 "다음" 가능 | 소리 없이 도입 완료로 기록 | 재생이 확인된 뒤에만 "다음" 활성. 부모 넘기기는 audioOk:false로 기록 |
| iPad 가로 화면에서 정답 피드백과 "다음"이 화면 아래로 밀림 | 아이가 스크롤해야 진행 | 보기 2열 배치, 피드백으로 자동 이동 |
| 앱 전환 후 돌아오면 소리 실패가 아니어도 경고 배너 | 불필요한 부모용 버튼 노출 | 먼저 다시 재생을 시도하고 실패할 때만 배너 |
| 기록 비교 키의 정렬 오류 (병합 구현 중 테스트로 발견) | 기록 없는 사본이 최신으로 판정 | 필드별 비교로 수정 |

손대지 않은 것과 이유:
- 퀴즈 화면의 흐름·그림·연출. 탐정·방탈출형으로 교체할 층이라 다듬지 않았다.
- 세션 순서(복습 먼저, 새 단어 나중). 복습이 밀리면 그 주 책 단어가 15분 안에 못 나올 수 있다. 새 장르 설계에서 "그 주 단어 우선, 복습은 사이사이"로 바꾼다.
- 채점 규칙이 퀴즈 진행 코드(`session.js`) 안에 섞여 있다. 새 장르가 같은 규칙을 쓰려면 분리가 필요하다. 탐정형 구현의 첫 단계로 한다.

## 10. 탐정·방탈출형 설계안 비교 (2026-11-11, 안 1 승인 후 구현됨 — 구현 기록은 11절)

전제: 사건 하나 = 주간 팩 하나(8~10개 단어) = 장면 하나. 바꿀 수 없는 조건(NEXT_SESSION.md)과 채점 규칙(3절)은 그대로다. 아래 수치 중 분당 인출 횟수와 제작량은 [estimate]이며 아이 사용 관찰은 없다.

### 10.1 설계안

- 안 1. 현장 수사형: 사건 장면 하나를 조사한다. 한 화면에 한 번의 인출을 하고 진행 순서는 고정이다.
  - 단서 수집(도입): 물건을 눌러 단어 소리·뜻 확인. 소리가 재생돼야 "다음".
  - 현장 확인(depth 1): 소리를 듣고 장면 속 물건(그림, 없으면 뜻 글자) 고르기.
  - 증언(depth 2): 증인이 단어를 말함 → 뜻 고르기.
  - 진술서(depth 3): 책 예문의 빈칸. 문장 음성은 답한 뒤에만.
  - 금고 암호(depth 4): 들은 단어의 철자 타일.
  - 복습은 "미해결 사건 파일"로 사이사이 삽입.
- 안 2. 방탈출형: 방 3개, 방마다 자물쇠 3개. 자물쇠 하나 = 카드 하나, 풀어야 다음 방으로 이동. 방 안에서 물건을 조사해 힌트를 얻는다.
- 안 3. 심문형: 용의자 3~4명의 진술(책 예문 변형)을 읽고 모순·단어를 찾아 범인을 추리. 대화 글 중심.

### 10.2 비교

| 기준 | 안 1 현장 수사 | 안 2 방탈출 | 안 3 심문 |
|---|---|---|---|
| depth 1~4 대응 | 1 소리→물건, 2 증언, 3 진술서, 4 금고. 현행 문항 유형과 1:1 | 자물쇠마다 depth 지정 가능. 자물쇠가 앞 자물쇠에 막힘 | 3(문맥)이 자연스럽고 1(소리→그림) 약함, 4는 억지 |
| 분당 인출 횟수 [estimate] | 6~7. 근거: 1회 ≈ 9초(재생 1.5 + 판단 4 + 피드백 3~4) | 2~3. 방 이동·연출·힌트 탐색 포함 1회 20~30초 | 2.5~4. 진술 읽기 15~25초 |
| 15분 내 소화량 [estimate] | 학습 2분 제외 13분 × 6 = 약 78회. 계획량(새 5×2라운드 + 복습 25 + 재도전 약 5 = 약 40회) 수용 | 약 30~40회. 복습 꼬리가 잘림. 계획 규칙 위반 위험 | 약 35~50회. 읽기 부담으로 편차 큼 |
| 막힘 위험 | 낮음. 오답은 공개 후 진행, 재도전은 4문항 뒤 | 높음. 못 풀면 정체, 15분 소모 | 중간 |
| 그림 제작 비용 | 장면 배경 1 + 물건 SVG 8~10. 현행 방식 그대로. 추상어는 글자 단서 카드 | 배경 3 + 물건 + 자물쇠. 사건당 약 3배 | 인물 3~4 + 배경 1. 대신 사건당 이야기 집필 필요 |
| 독서 전이 | 책 예문·쪽을 진술서·종료 화면에 연결 | 연결 약함 (퍼즐 중심) | 높음 (문장 단위) |
| 반복 동기 | 중간. 사건 종결·증거판 | 높음. 단, 막힘과 교환 | 중간. 사건 이야기 소진 |
| 위험 | 연출이 약하면 현행 퀴즈와 차이가 작음 | 놀이가 학습 시간 점유 | 글 읽기 능력이 인출 능력과 섞임 |

### 10.3 선택: 안 1 (현장 수사형) + 사건 종결 장치 1개

선택 근거: 15분 상한에서 분당 인출 횟수가 가장 높고, 그림·집필 비용이 현행 수준이며, 채점·음성 규칙과 충돌하는 지점이 없다. 안 2의 동기 요소는 "금고 열기"(사건 종결, depth 4)로 한 번만 가져온다. 안 3의 문맥 요소는 depth 3 진술서에 흡수한다.

- 세션 순서 변경: 그 주 단어 도입 → depth 1 → depth 2 순으로 진행하고, 복습 카드는 새 단어 2~3개마다 1개씩 끼워 넣는다. 15분이 모자라면 복습 꼬리를 자른다. (현행은 복습이 앞이라 책 단어가 밀릴 수 있음, 9절)
- 보상: 혼자 맞힌 단어의 물건에 불이 켜지는 것(현행 유지)과 "사건 해결" 표시. 사건 해결 조건은 협동 목표(두 아이가 합쳐 해결한 사건 수)로만 표시, 아이별 점수 비교 화면 없음. 보상은 일정에 영향 없음.
- 게임 결과는 `assist: audio`로 기록하고, 종료 화면에 "소리 도움 결과"로 표시(3절 유지).
- 구현 범위: `main.js`의 학습·문항·종료 화면 교체. `questions.js`의 문항 생성, `engine.js`, `srs.js`, `store.js`, `sync.js`, `audio.js`는 유지. 문항 유형은 현행 5종을 새 화면 문구·배치로 재포장하는 수준이며 새 인출 유형은 추가하지 않는다.
- 데모: "유령의 집 사건" 1편(그림 SVG 9개, 팩 9카드).

### 10.4 반증 조건과 한계

- 장면 속 물건 고르기는 소거법으로 풀릴 수 있다. 보기를 4개로 제한하고 소요 시간(`ms`)과 오답률 분포로 추측 응답을 점검한다.
- 서사 연출이 인출 시간을 20% 이상 늘리면(현행 퀴즈 대비 분당 인출 횟수) 연출을 줄인다. 현행 퀴즈 화면의 실측치가 없으므로 구현 후 첫 사용 로그로 처음 측정한다.
- 이 설계가 현행 퀴즈보다 기억·독서 전이에 낫다는 근거는 없다. 2주 사용 후 다음 날 정답률과 아이 반응을 보고 재판단한다.

## 11. 탐정형 구현 기록 (2026-11-11)

### 11.1 세션 흐름

소리 확인 → 사건 접수(그 사건의 첫 방문 1회) → 단서 수집(새 단어 도입, 최대 5개) → 새 단어 문항(depth 1 전체 → depth 2 전체) 사이에 복습 삽입 → 남은 복습 → 수사 보고서.

- 순서 규칙(`session.js`): 새 단어 문항 2개마다 만기 복습 1개(`REVIEW_EVERY = 2`), 나머지 복습은 맨 뒤. 15분이 되면 현재 문항 뒤에 끝나므로 잘리는 것은 복습 꼬리다. 예: 새 단어 4개·복습 5개인 날의 순서는 LLLL NNR NNR NNR NNR R (L 도입, N 새 단어 문항, R 복습).
- 화면과 문항 유형의 대응(문항 생성 코드는 그대로, 문구와 배치만 다름):

| 화면 | 문항 유형 (depth) | 비고 |
|---|---|---|
| 현장 확인 | sound-pic (1) | 보기 4개가 모두 현재 장면의 물건이면 장면 안에서 물건을 누른다. 아니면 그림 격자 |
| 증언 듣기 | sound-meaning (1) | 그림이 없는 단어 |
| 증언 | word-meaning (2) | |
| 진술서 | cloze (3) | 문장 음성은 답한 뒤에만 |
| 금고 암호 | spell (4) | |

- 복습 문항에는 "미해결 파일(복습)" 표시가 붙는다.

### 11.2 사건 상태 (`case.js`)

카드 기록에서 매번 계산하며 저장하지 않는다. 따라서 동기화·병합 규칙과 일정에는 영향이 없다.

| 용어 | 정의 | 되돌아가는가 |
|---|---|---|
| 단서 확보 | 그 단어를 한 번이라도 혼자 맞힘 (`depthDone >= 1`) | 아니오 |
| 불 켜짐 | 지금 '앎'이고 streak > 0 (v0와 동일) | 예. 틀리면 꺼짐 |
| 사건 해결 | 팩의 모든 단어를 만났고, T1·T2 단어를 모두 확보 | 아니오 |
| 금고 | depth 4 대상(T1, depth_target 4)이면서 철자 문항이 가능한 단어 수. 그 단어를 depth 4에서 혼자 맞히면 1칸 열림 | 아니오 |
| 사건 종결 | 해결 + 금고 전부 열림 (금고 대상이 없으면 해결 = 종결) | 아니오 |

- 현재 사건: 아직 만나지 않은 단어가 있는 첫 팩(새 단어를 뽑는 순서와 같음), 없으면 종결되지 않은 첫 팩.
- 데모 "유령의 집 사건"(아들 팩, 9단어, 금고 3칸)을 전부 정답으로 진행하면 2일차에 해결, 6일차(세션 5회)에 종결된다. 복습 간격 1·3일에 따른 결과이며 통합 테스트로 확인했다.
- 첫 화면에는 두 아이를 합친 숫자(해결한 사건 수, 확보한 단서 수)만 표시한다. 아이별 사건·단서 수는 각자의 사건 수첩에만 있다.

### 11.3 승인된 설계안(10.3)에 없던 구현 결정

- "단서 확보"와 "불"을 분리했다. 보상(사건 진행)은 되돌아가지 않게 하고, 현재 기억 상태는 불로 따로 보여 준다. 한 값으로 합치면 복습에서 틀릴 때 해결된 사건이 미해결로 돌아간다.
- T3(노출만) 단어는 사건 해결 조건에서 "만남"만 요구한다. T3는 틀려도 복습이 없어 확보를 요구하면 사건이 영영 해결되지 않는다.
- 금고는 한 번의 퍼즐이 아니라 depth 4 문항들의 누적이다. depth 4는 복습 단계에서만 나오므로 사건 종결은 해결보다 며칠 뒤다.
- 사건 접수 화면(이야기 2문장, 버튼 1개)을 사건당 1회 넣었다. 15분 안에서 시간을 쓴다.
- 데모 장면의 물건 위치를 겹치지 않게 재배치했다(누르는 영역이 장면 너비의 17%). `tools/make_demo.py`에 같은 값을 반영했다.
- 단서 수집 화면의 "다음"을 듣기 버튼 줄로 옮겨 iPad 가로 화면에서 스크롤 없이 보이게 했다(Chromium 1024×700 확인, 실기기 미확인).
- 세션 기록에 응답 횟수(`answered`)를 추가했고 수사 보고서에 분당 응답 횟수를 부모 확인용으로 표시한다. 10.4의 측정을 위한 것이다.
- 장면 그림이 없는 팩(실제 책 팩)은 사건 제목을 팩 이름으로 쓰고 현장 확인은 그림·글자 격자로 나온다. 실제 팩으로는 실행해 보지 않았다.

### 11.4 확인되지 않은 것

- 분당 인출 횟수 추정(6~7회)의 실측. 자동 테스트의 수치는 사람 속도가 아니라서 근거가 되지 않는다.
- 장면 안 물건 고르기가 격자보다 쉬운지(소거법, 위치 기억). 같은 물건이 항상 같은 자리에 있으므로 소리가 아니라 위치로 답할 가능성이 있다. 첫 사용 로그의 `ms`와 depth 2 정답률로 점검한다.
- 아이 반응, iPad 실기기 동작 전부.
