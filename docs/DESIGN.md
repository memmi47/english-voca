# 설계 결정 기록 (프로토타입 v0)

작성일 2026-11-11. 현재 요구의 기준은 착수 프롬프트와 `reference/weekly-tool/Game_Handoff.md`. 과거 벤치마크의 동물 수집 콘셉트와 전체 목록 승인 순서는 채택하지 않았다.

## 1. 게임 콘셉트 비교와 선택

판단 기준: 실제 독서 전이, 반복 동기, iPad 조작 부담, 음원·그림 제작 비용.

| 콘셉트 | 독서 전이 | 반복 동기 | iPad 조작 | 제작 비용 | 비고 |
|---|---|---|---|---|---|
| A. 장면 탐험 (한 장면에 8~10개, 소리→그림→문맥) | 높음. 책의 문장·쪽을 카드에 연결 | 중간. 불 켜기, 장면 복원 | 낮음 (탭만) | 중간. 장면당 그림 8~10개 | 선택 |
| B. 턴제 카드 수집 (Lingo Legend 유형) | 낮음. 수집이 어휘와 분리될 위험 | 높음 | 중간 | 높음. 카드·밸런스·캐릭터 | 반복 동기는 크나 비용이 크고 점수·수집이 기억 상태와 섞임 |
| C. 짧은 이야기 해결 (문맥 중심) | 높음. 문장 단위 | 중간 | 낮음 | 높음. 장면별 이야기 집필 | 구동사·추상어에 적합. A의 depth 3에 일부 흡수 |

선택은 A. 근거:
- 한 장면은 주간 팩 8~10개 단위와 맞고, 소리→그림·장면→문맥 순서를 한 화면 구조로 구현할 수 있다.
- 추상어는 그림 대신 문맥 문항으로 내려간다. 같은 틀에서 depth 1~4가 모두 작동한다.
- B의 반복 동기는 보상을 기억 상태와 분리해야 하는 위험이 있어 첫 버전에서 배제. 보상은 "혼자 맞힌 단어의 물건에 불이 켜짐" 하나로 한정하고, 일정에는 영향을 주지 않는다.
- 반증 조건: 2주 사용 후 아이가 장면 반복을 지루해하면 B의 수집 요소를 별도 선택 활동으로 추가 검토한다. 이것은 설계 가설이며 아이들에게 검증되지 않았다.

## 2. 한 세션의 흐름

소리 확인 → 복습(만기 T1/T2, 상한 25) → 새 단어 장면 학습(최대 5개/회, 설정 3~10) → 1라운드 depth 1 → 2라운드 depth 2 → 오답 카드의 간격 재도전 → 종료 화면(혼자 맞힌 단어, 내일 다시 볼 단어, 책에서 찾을 쪽).

- 새 카드는 학습 직후 depth 1(소리→그림, 그림 없으면 소리→뜻), 이어 depth 2(단어→뜻)에서 인출. 정답이 화면에 먼저 나타나지 않는다. 문장 빈칸(depth 3)에서는 문장 음성이 답을 말하므로 답한 뒤에만 재생한다.
- depth 3·4는 복습에서 한 단계씩 올린다 (`depthDone+1`, 상한 `min(depth_target, 티어 상한)`). T3는 2, T2는 3, T1은 4까지. 예문에 해당 단어가 없으면 depth 3으로 올리지 않고 낮은 depth로 대체한다.
- 오답이면 정답과 음성을 보여 주고, 같은 카드를 4문항 뒤 비채점 재도전으로 다시 낸다.
- 세션 15분: 화면이 보일 때만 시간이 흐르고, 같은 날 여러 번 해도 합산 15분. 종료 시점은 현재 문항이 끝난 뒤.

## 3. 채점과 복습 규칙

| 결과 | 기록 | 일정 효과 |
|---|---|---|
| 첫 시도 정답, 힌트 없음 (independent) | streak+1 | T1/T2: 1·3·7·14·30일. T3: 일정 없음 |
| 힌트 사용 후 정답 (hinted) | 별도 기록 | 가정: streak 유지, 다음 날 다시. 승급 없음 |
| 첫 시도 오답 (wrong) | streak 0 | 다음 날 |
| 오답 후 재도전 정답 (retry_success) | 별도 기록 | 일정에 영향 없음 |
| 소리 실패로 건너뜀 (skipped_no_audio) | 별도 기록 | 채점 안 함 |

- 같은 카드는 하루 1회만 채점. 만기 전 연습은 간격을 늘리지 않는다 (`core.py record_review`와 동일).
- 모든 게임 결과는 `assist: audio`로 기록한다. 종이 책에서 혼자 읽은 결과와 합치지 않는다. 진단 구간 추정 앎은 `inferred`로 따로 두고 일정을 만들지 않으며, 게임에서 틀리면 직접 오답으로 덮어쓴다.
- 힌트의 일정 처리는 요구 문서에 없는 제 가정이다. 부모가 바꾸려면 `srs.js applyScore`의 한 곳이다.

## 4. 데이터와 저장

- 원본 `reference/weekly-tool/vocabulary.json`, XLSX는 수정하지 않는다. `tools/build_catalog.py`가 게임용 `game/data/catalog.json`(6,591 카드, 약 1.0MB)을 만든다.
- 팩은 주간 도구 `/export?profile=...` JSON을 그대로 읽는다 (`approved_packs`, `local_cards`, `card_states`, `reviewed_audio`). 데모 팩 두 개는 같은 형식이며 `_sample: true`로 표시된다.
- 저장은 브라우저 localStorage, 아이별 키(`catchup.v1.p.son` / `.daughter`)와 공용 설정 키. 가져오기는 병합 전용이다. 팩 지문이 같으면 변경 없음, 다르면 tier·depth·context·page만 갱신하고 진도 필드는 건드리지 않는다. 다른 아이의 파일은 거부한다.
- 데모(sample)와 실제 팩이 같은 card_id를 쓸 때: 데모는 실제 레코드를 건드리지 않고, 실제 팩은 데모 레코드를 새 기록으로 대체한다. 학습만 하고 채점되지 않은 카드는 다음 세션에서 새 단어로 다시 나온다.
- 내보내기는 아이별 JSON. `card_states`는 주간 도구와 같은 `[known, origin, due, streak]` 순서이며 데모 카드는 제외한다.
- 주의: localStorage는 브라우저·기기별이다. Mac과 iPad의 기록은 자동으로 합쳐지지 않는다. 정식 운영 전 "한 기기에서만 진행" 또는 서버 저장 도입을 결정해야 한다 (미결).

## 5. 음성

- 공유 `<audio>` 1개를 "소리 켜고 시작" 탭에서 해제하고, 요청 토큰으로 오래된 재생을 취소하며, 같은 키 재생은 1.2초 안에서 중복 억제, 다시 듣기는 강제 재생. iOS 17+는 `navigator.audioSession.type='playback'`으로 무음 스위치를 통과시킨다. 근거와 한계는 `docs/research/audio_ipad_research.md`.
- 실패(차단, 로드 오류, 5초 타임아웃)는 배너와 다시 듣기를 띄우고 현재 문항을 유지한다. 소리에 의존하는 문항(소리→그림, 철자)은 복구 전까지 선택지를 잠근다. 부모용 "소리 없이 넘기기"는 채점하지 않는다.
- 음원 키는 card_id(뜻·시제별로 분리됨), 문장은 `card_id#s`. `audio/manifest.json`의 status: `dev_tts`(임시 합성), `candidate`, `human_approved`(사람 검수), `rejected`. 승인은 앱의 `#/review`에서 검수 로그를 내보내고 `tools/audio_tool.py apply-review`가 반영한다. 파일 해시가 바뀌면 승인이 해제된다. 어떤 도구도 스스로 `human_approved`를 만들지 않는다.
- 현재 음원 20개는 모두 ffmpeg flite(slt) 합성이며 `dev_tts`다. 발음 검증용이 아니다. 실제 음원은 부모 녹음, 또는 라이선스를 확인한 TTS로 교체한다. 라이선스는 조사 문서 3절, 소규모 세트의 제작·검수·교체 절차는 아래 6절.

## 6. 음원 제작·검수·교체 절차 (소규모 세트로 검증)

1. `tools/audio_sources.json`에 키·텍스트 정의 (목표 단어와 예문 별도).
2. 파일 준비: 개발용은 `python3 tools/audio_tool.py build`. 실제 음원은 같은 키 이름의 mp3/m4a를 `game/audio/reviewed/`에 넣고 매니페스트 항목 `file`/`sha256`을 갱신.
3. 앱 `#/review`에서 들어 보고 승인/반려, 로그 내보내기.
4. `python3 tools/audio_tool.py apply-review audio_review_log.json`. 해시 불일치는 거부.
5. 파일을 교체하면 승인은 `candidate`로 내려가 재검수가 필요.
전체 음원 일괄 생성 여부는 이 절차를 데모 20개로 한 번 돌린 결과(검수 시간, 수정 비율)를 보고 판단한다. 지금은 판단 근거가 없다.

## 7. 데이터 점검에서 나온 부모 검토 항목 (상세: docs/research/data_audit.md)

- starter 500의 첫 뜻 문제 (light=불을 붙이다, water=물을 주다 등), 같은 한글 뜻 25쌍, IPA 오류(use, lead, minute 등), 불규칙 과거형 84장 중 75장이 원형 뜻과 동일, image_type 오분류, depth 4 후보 21개가 부적절(be, do 등).
- 게임 반영: 동음 쌍(right/write)은 소리 기반 보기에서 서로 제외. 나머지는 데이터 수정 사항이라 건드리지 않았다.

## 8. 이번에 하지 않은 것

실제 책 표본 기반 팩, 말장난 코너, 월간 인쇄 연동, 듣기 진단(150문항), 서버 저장, 전체 음원, 소리 도움 없는 읽기 확인 화면. 모두 근거 입력 또는 결정 대기.
