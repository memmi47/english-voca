# C-009 가끔 실패하는 브라우저 검사(번개 라운드)의 원인을 찾아라

- 상태: 조사 완료 (20회 미재현, 검사 변경 없음)
- 담당 층: 실행 (Terra). 원인이 코드에 있으면 Sol.
- 선행 카드: 없음
- 브랜치: `codex/flaky-lightning` (기준 `claude/modest-mccarthy-3gadjk`)

## 목표

자동 검사가 코드와 무관하게 실패해 PR을 막거나, 진짜 결함을 "가끔 실패"로 덮는 일이 없어진다.

## 배경

- C-006 작업 중 `node tests/cards_e2e.cjs`의 첫 실행에서 번개 라운드의 점수·보상 확인 1건이 실패했고, 같은 코드로 다시 돌리자 통과했다(`docs/tasks/C-006.md` 결과). 이후 Claude가 두 번 연속 돌렸을 때는 재현되지 않았다.
- 번개 라운드 화면 코드는 `cards/js/main.js`(`lightning` 근처), 규칙은 `cards/js/map.js`의 `Lightning`.

## 할 일

1. 브라우저 검사를 최소 20번 돌려 실패 횟수와 실패한 검사 이름·출력을 모은다(`for i in $(seq 20); do node tests/cards_e2e.cjs > /tmp/e2e_$i.txt 2>&1; done` 등). 다른 무거운 작업을 동시에 돌린 경우와 아닌 경우를 나눠 적는다.
2. 원인을 찾는다: 검사의 대기 방식(시간 의존), 난수, 화면 코드의 경쟁 상태 중 어느 쪽인지.
3. 원인이 검사 쪽(대기 부족 등)이면 `tests/cards_e2e.cjs`를 고친다. 검사 조건을 약하게 하거나 빼지 않는다. 고정 시간 대기(`waitForTimeout`)를 늘리는 대신 조건 대기(`waitForFunction`, `waitForSelector`)로 바꾼다.
4. 원인이 게임 코드 쪽이면 고치지 말고 재현 방법과 근거를 결과에 적는다(Claude가 고친다).
5. 20번에 한 번도 실패하지 않으면 그 사실과 실행 환경을 적고 끝낸다. 추측으로 고치지 않는다.

## 고칠 수 있는 파일

- `tests/cards_e2e.cjs`(원인이 검사 쪽일 때만)
- `docs/tasks/C-009.md`의 결과, `docs/tasks/BOARD.md`의 상태, `docs/WORKLOG.md` 8절에 한 줄

## 바꾸면 안 되는 것

- `cards/js/*`, `cards/css/*`, `cards/data/*`, 다른 검사 파일. 기존 검사를 지우거나 약하게 하지 않는다.
