# C-002 변신 형태 자료(`forms.json`)와 부모 검수표를 만들어라

- 상태: 구현 완료·교차 검토 대기 (2026-11-16 승인 예외 적용)
- 담당 층: 설계 (Astra: 선별 규칙과 검증 방법) → 구현 (Sol: 생성기와 검사)
- 선행 카드: 없음
- 브랜치: `codex/word-forms` (기준 `claude/modest-mccarthy-3gadjk`)

## 목표

아이가 이미 만난 단어의 다른 형태(went, children, stopped)를 책에서 알아보도록, 게임이 쓸 수 있는 정확한 형태 목록이 생긴다.

## 배경

- `docs/LEARNING_VALUE_SPEC.md` 2.6절. 게임은 "원형 찾기" 카드 한 종류로 시작한다: 변신한 형태를 보여 주고 원형 세 개 중에서 고르게 한다. 시제의 한글 뜻은 쓰지 않는다.
- DB(`reference/weekly-tool/vocabulary.json`)에 `kind: "불규칙 과거형"` 카드 84장이 있다(P1 71, P2 13). 불규칙 복수는 DB에 없다. 단수형이 덱에 있는 것은 최소 25개다(child, man, woman, foot, tooth, mouse, goose, person, leaf, knife, wolf, life, wife, shelf, thief, half, sheep, fish, deer, ox, scarf, elf, calf, hoof, cactus).
- 규칙 변화 중 철자가 바뀌는 후보 [verified, 단순 규칙으로 센 값]: 동사 1,165개 중 e 탈락 391, 자음 겹침 73, y→ied 31. 명사 2,660개 중 -es 171, -ies 146.
- 틀린 형태 하나가 아이에게 잘못된 철자를 가르친다. 그래서 수보다 정확도가 먼저다.

## 만들 것

`cards/data/forms.json`

```json
{
  "schemaVersion": 1, "status": "draft",
  "source": { "path": "reference/weekly-tool/vocabulary.json", "sha256": "..." },
  "counts": { "forms": 0, "bases": 0, "byKind": {}, "byRule": {} },
  "forms": [
    { "id": "F:W1234:past", "base": "<catalogue의 카드 id>", "baseForm": "run", "form": "ran",
      "kind": "past | pp | ing | s3 | plural", "rule": "irregular | e-drop | double | y-ied | es | y-ies | plain",
      "source": "db | list | rule", "clash": ["<같은 철자인 다른 카드 id>"], "lookalikes": ["rain", "ruin"], "reviewed": false }
  ]
}
```

- `id`는 원형 카드 id와 종류로 만든다. 한 번 낸 id는 바꾸지 않는다(아이의 변신 기록이 이 id로 저장된다).
- `base`는 `cards/data/catalogue.json`에 있는 `learningKind: "vocab"`의 한 단어 카드만. 표현과 기능어는 제외.
- `clash`: 변신한 철자가 다른 카드의 원형과 같을 때(left, saw, found, rose) 그 카드 id를 적는다. 게임은 이런 형태를 문제로 내지 않거나 따로 다룬다.
- `lookalikes`: 오답 보기로 쓸 원형 후보 2~4개. 덱 안의 단어 중 철자가 닮은 것(첫 글자 같음, 길이 비슷, 편집 거리 2 이하 우선). 정답 원형과 혼동 묶음(`confusionGroups`)이 겹치는 단어는 넣지 않는다.

`docs/research/forms_review.md`와 `.csv`: 부모가 훑어볼 표. 원형, 한글 뜻, 형태, 종류, 규칙, 출처. 규칙으로 만든 것과 목록에서 온 것을 구분하고, 확신이 낮은 것을 위에 둔다.

## 선별 규칙 (Astra가 확정해 결과에 적는다)

1. 불규칙(DB 84장 + 불규칙 복수 목록)은 전부 넣는다. 과거분사는 과거형과 다를 때만(went / gone).
2. 규칙 변화는 철자가 바뀌는 것만 넣는다(e 탈락, 자음 겹침, y→i, -es). 그대로 붙는 것(walked, cats)은 넣지 않는다.
3. 애매하면 뺀다. 예: 셀 수 없는 명사의 복수, 강세에 따라 자음을 겹치는지 달라지는 동사(visit / admit), 미국·영국 철자가 갈리는 것(traveled), 품사가 둘이라 어느 변화인지 불분명한 것.
4. 검증 방법을 하나 이상 둔다. 예: DB의 책 말뭉치 수치(`corpus_token_count` 등)나 공개 사전 자료와 대조. 외부 유료 도구는 쓰지 않는다. 대조하지 못한 형태는 `source: "rule"`로 남기고 검수표 위쪽에 둔다.

## 완료 기준

```sh
python3 -I tools/make_forms.py            # forms.json과 검수표 생성
python3 -I tools/make_forms.py --check    # 다시 만들어도 같은 결과, 아래 검사 통과
```

검사 항목: 모든 `base`가 catalogue에 있음, `id` 중복 없음, 같은 `(base, kind)` 중복 없음(be의 past에 한해 was/were 두 variant 허용; `(base, kind, variant)` 고유), `form`이 `baseForm`과 다름, `lookalikes`가 2개 이상이고 정답 원형·혼동 묶음을 포함하지 않음, `clash`가 실제로 같은 철자인지, 불규칙 84장과 불규칙 복수 25개를 포함·제외·보류 사유로 빠짐없이 추적함. 원형 동일 과거 6장/복수 3개는 제외, half/deal은 뜻 검토 전 보류.

결과에 적을 것: 종류·규칙별 개수, 뺀 것과 이유의 개수, 검증 방법과 대조하지 못한 개수.

## 막히면

정확도를 확인할 방법이 없는 묶음은 넣지 말고 개수와 예시만 결과에 적는다.

### 질문 (2026-11-16, 구현 전 보류)

1. 과거형 `cut/hit/hurt/let/put/read` 6장과 일반 복수 `sheep/fish/deer` 3개는 원형과 철자가 같다. “전부 넣음”과 `form != baseForm`을 동시에 만족할 수 없다. 게임 목록에서 제외하되 검수표에 전수 기록하고, 완료 기준을 포함·제외 사유의 전수 추적으로 바꾸어도 되는가?
2. `be → was/were`는 같은 `(base, past)` 2개다. 두 형태를 유지하려면 종류 외에 변형을 구분하는 ID·고유성 계약이 필요하다. 두 형태용 ID를 허용할지 하나를 선택할지 결정이 필요하다. 현재 ID 계약을 임의로 바꾸지 않았다.
3. 필수 목록의 `half`는 catalogue 뜻이 `절반의`(형용사·명사), DB 과거형의 원형 `deal`은 `약속`(명사·동사)이다. halves·dealt를 현재 뜻으로 설명하기 어려우므로 Claude가 원형 뜻을 검토할 때까지 보류해도 되는가? C-002에서는 원본 뜻을 바꾸지 않는다.

### 사용자 결정 (2026-11-16, 구현 재개)

사용자가 세 권장안 모두 진행을 지시했다. 원형 동일 과거 6장(cut/hit/hurt/let/put/read)·복수 3개(sheep/fish/deer)는 게임 목록에서 제외하고 검수표에 전수 기록한다. be의 was/were는 둘 다 별도 카드로 포함하며 `variant`를 was/were로 명시하고 ID는 `F:<base>:past:was` / `F:<base>:past:were`로 고정한다. 다른 단일 형태 ID는 `F:<base>:<kind>`다. 고유성 검사는 be의 두 past만 `(base,kind,variant)`로 허용한다. half/deal의 모든 새 형태는 현재 뜻 검토 전 보류하고 나머지를 진행한다. 한글 뜻·catalogue·DB는 수정하지 않는다. 위 질문은 이 결정으로 해소됐으며 과거 결과는 보류 당시 이력이다.
