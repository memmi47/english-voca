# T-006 뜻 고르기의 오답 보기 하나를 같은 주제·같은 품사에서 뽑아라

- 상태: 대기
- 담당 층: 실행 (Sonnet)
- 선행 카드: C-003(완료), T-011(병합 뒤 시작)
- 브랜치: `t-006-theme-option` (기준 `claude/modest-mccarthy-3gadjk`. 푸시하지 않는다. 설계 층이 검토 후 병합한다)

## 목표

뜻 고르기 카드가 소거법으로 풀리지 않게 된다. 보기 셋 중 하나는 정답과 같은 주제의 단어라서, 뜻을 실제로 알아야 고를 수 있다.

## 배경

- `docs/LEARNING_VALUE_SPEC.md` 2.5절. 지금은 오답 둘 다 그림 종류(`type`)만 맞춘 무작위다(`cards/js/deck.js`의 `_options`).
- `docs/research/theme_audit.md`(C-003): 같은 주제·같은 품사 후보가 5개 미만인 카드가 뜻 고르기 109장, 주제가 비었거나 이름에 `기타`·`보완`이 들어간 카드가 200장이다. 그래서 일괄 적용하지 않고, 후보가 모자라면 지금 방식으로 되돌린다.
- 실제 카드 목록 `cards/data/catalogue.json`의 카드에는 `theme`, `pos`가 있다. 시뮬레이터가 읽는 `cards/data/catalog.json`에는 없다.

## 규칙 (설계 층 결정)

1. 대상: 듣고 고르는 카드(`isSight`)가 아닌 카드. 정답 카드에 `theme`과 `pos`가 모두 있고, `theme`에 `기타`·`보완`이 들어 있지 않을 때만 적용한다.
2. 후보: `theme`과 `pos` 문자열이 정답과 정확히 같은 카드 중, 지금 규칙으로 보기가 될 수 있는 것(자기 자신 아님, 듣기 카드 아님, 혼동 묶음을 공유하지 않음, 화면 표시가 정답과 다름).
3. 후보가 5개 이상이면 오답 하나를 그 후보에서 무작위로 뽑고, 나머지 하나는 지금 방식(같은 그림 종류 → 전체)으로 뽑는다. 후보가 5개 미만이면 둘 다 지금 방식이다.
4. 색인은 `indexOf`에 `theme|pos` 키의 Map을 추가해 만든다. 판마다 전체 목록을 훑지 않는다.
5. 끄는 설정: `CFG.themeOption`(기본 `true`). `false`면 지금 동작과 완전히 같다. 시험용 주소 옵션 `?theme=off`.
6. `theme`·`pos`가 없는 카드 목록(시뮬레이터의 `catalog.json`)에서는 난수를 쓰는 순서와 횟수가 지금과 완전히 같아야 한다. 시뮬레이션 기준값이 바뀌면 안 된다.

## 고칠 수 있는 파일

- `cards/js/deck.js`(`indexOf`, `_options`, `CFG`), `cards/js/main.js`(주소 옵션 한 줄)
- `tests/cards.test.mjs`, `tests/cards_e2e.cjs`(기대값이 난수 순서 때문에 바뀌는 곳만)
- `docs/tasks/T-006.md`의 결과, `docs/tasks/BOARD.md`의 상태, `docs/LEARNING_VALUE_SPEC.md` 2.5절의 상태 한 줄

## 바꾸면 안 되는 것

- 저장 형식(`SCHEMA`), 복습 간격, 박쥐·훑기·성 규칙, `cards/data/*`, `tools/sim_learning.mjs`, `reference/`.
- 혼동 묶음과 같은 뜻 제외 규칙을 약하게 하지 않는다.
- 기존 검사를 지우거나 약하게 하지 않는다. 난수 순서가 달라져 기대값이 바뀌는 검사는 고치되 무엇을 왜 바꿨는지 결과에 적는다.

## 완료 기준

```sh
node --test tests/*.test.mjs
node tests/cards_e2e.cjs                                   # 필요하면 NODE_PATH=$(npm root -g)
node tools/sim_learning.mjs --set chosen --seeds 5         # 병합 전 기준 브랜치의 출력과 글자 하나까지 같다
```

새 단위 검사:

1. 주제·품사 후보가 5개 이상인 카드: 200번 뽑으면 매번 보기 셋 중 정답이 아닌 하나 이상이 정답과 같은 `theme`·`pos`다.
2. 후보가 4개인 카드, `theme`에 `보완`이 든 카드, `theme`이 없는 카드: 지금 방식과 같은 결과(같은 씨앗으로 `themeOption` 켠 것과 끈 것의 보기가 같다).
3. 혼동 묶음을 공유하는 같은 주제 카드는 보기로 나오지 않는다.
4. 실제 `cards/data/catalogue.json` 전체에서 뜻 고르기 카드마다 보기 셋이 서로 다른 표시를 갖는다(전수, 한 번씩).

결과에 적을 수치: 실제 카드 목록에서 규칙 3이 적용되는 카드 수와 되돌아가는 카드 수.
