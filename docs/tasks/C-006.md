# C-006 뜻 고르기의 나머지 오답 보기도 같은 품사에서 뽑아라

- 상태: 검토 (구현·검사 완료, Draft PR 제출)
- 담당 층: 구현 (Sol). 막히면 Astra.
- 선행 카드: T-006(완료), T-009(완료)
- 브랜치: `codex/pos-option` (기준 `claude/modest-mccarthy-3gadjk`)

## 목표

뜻 고르기 카드에서 품사만 보고 보기 하나를 지울 수 없게 된다. 찍어서 맞힐 확률이 약 50%에서 약 33%로 내려간다.

## 배경

- T-006이 오답 하나를 정답과 같은 주제·같은 품사에서 뽑게 했다(`cards/js/deck.js`의 `_options`, `themeKey`, `indexOf`의 `byTheme`). 나머지 하나는 예전 방식(같은 그림 종류 `type` → 전체)이라 품사가 다른 보기가 자주 나온다.
- 실제 카드 목록에서 뽑아 본 예 [verified, 2026-11-17]: happy → 행복한 / 살아 있는 / **자연**, quickly → 빠르게 / 앞으로 / **흡혈귀**. 굵은 보기는 품사만 봐도 지워진다.
- 이 카드는 예외적으로 Codex가 `cards/js/deck.js`와 `tests/cards.test.mjs`를 고친다(사용자 결정 2026-11-17). 다른 `cards/js/*` 파일은 고치지 않는다.

## 규칙 (설계 층 결정)

1. 대상: 듣고 고르는 카드(`isSight`)가 아니고 `pos`가 있는 카드. `theme`은 없어도 된다.
2. 같은 품사 후보: `pos` 문자열이 정답과 정확히 같은 카드(듣기 카드 제외). 색인은 `indexOf`에 `byPos` Map으로 한 번만 만든다. 품사 묶음이 수천 장일 수 있으므로 판마다 묶음 전체를 걸러 내지 않는다(기존 `draw`처럼 무작위로 최대 30번 뽑아 `take`로 넣는다).
3. 순서: (가) T-006의 같은 주제 보기(지금 그대로) → (나) 남은 자리를 같은 품사 묶음에서 `draw` → (다) 그래도 남으면 지금 방식(같은 그림 종류 → 전체)으로 채운다. 같은 품사 묶음이 5장 미만이면 (나)를 건너뛴다.
4. 기존 제외 규칙은 그대로다: 자기 자신, 혼동 묶음을 공유하는 카드, 화면 표시가 이미 나온 보기와 같은 카드는 넣지 않는다(`fits`, `take`가 이미 한다).
5. 끄는 설정: `CFG.posOption`(기본 `true`). `false`면 T-006 병합 뒤의 동작과 완전히 같다.
6. `pos`가 없는 카드 목록(시뮬레이터가 읽는 `cards/data/catalog.json`)에서는 난수를 쓰는 순서와 횟수가 지금과 완전히 같아야 한다. 규칙 회귀 검사가 이를 본다.

## 고칠 수 있는 파일

- `cards/js/deck.js`(`CFG`, `indexOf`, `_options`만), `tests/cards.test.mjs`(검사 추가)
- `docs/tasks/C-006.md`의 결과, `docs/tasks/BOARD.md`의 상태, `docs/WORKLOG.md` 8절에 한 줄

## 바꾸면 안 되는 것

- 저장 형식(`SCHEMA`는 3 그대로), 복습 간격, 박쥐·훑기·성·회오리 규칙, `cards/js/`의 다른 파일, `cards/data/*`, `tools/sim_learning.mjs`, `tests/fixtures/*`, `reference/`.
- 혼동 묶음·같은 뜻 제외 규칙을 약하게 하지 않는다.
- 기존 검사를 지우거나 약하게 하지 않는다. T-006의 검사 O1~O4는 그대로 통과해야 한다. 난수 순서가 달라져 기대값이 바뀌는 기존 검사가 있으면 고치되, 어느 검사를 왜 바꿨는지 결과에 적는다.

## 완료 기준

```sh
node --test tests/*.test.mjs             # 전부 통과 (지금 96)
node tests/cards_e2e.cjs                 # 전부 통과 (지금 149). 필요하면 NODE_PATH=$(npm root -g)
node tools/check_sim_baseline.mjs        # "simulation output unchanged". --update 를 쓰지 않는다
```

새 단위 검사(`tests/cards.test.mjs`, 이름은 O5부터):

1. O5: 같은 품사 카드가 5장 이상인 카드를 200번 뽑으면 오답 둘 다 정답과 같은 `pos`다(같은 주제 후보가 충분한 경우와 없는 경우 각각).
2. O6: `pos`가 없는 카드, 같은 품사 카드가 4장뿐인 카드는 `posOption`을 켠 것과 끈 것의 보기가 같은 씨앗에서 같다.
3. O7: 같은 품사이면서 혼동 묶음을 공유하거나 화면 표시가 같은 카드는 보기로 나오지 않는다.
4. O8: 실제 `cards/data/catalogue.json` 전체에서 뜻 고르기 카드마다 보기 셋의 표시가 서로 다르다(O4와 같은 방식, `posOption` 켠 상태). 그리고 오답 둘이 모두 같은 품사인 카드 수와 그렇지 않은 카드 수를 세어 결과에 적는다.

## 결과

- 기준: `9852d22`, 브랜치 `codex/pos-option`. 규칙 1~6대로 CFG.posOption 기본 true, 한 번만 만드는 byPos 색인(듣기 카드 제외), 주제 → 같은 품사 draw(최대 30회, 묶음 5장 이상) → 기존 type/전체 순서를 추가했다. 같은 뜻·혼동 묶음·자기 자신 제외는 기존 fits/take를 그대로 쓴다.
- 새 검사 O5~O8: 주제 후보 충분/부족 각각 200회 모두 같은 품사 오답 2개, 품사 없음/묶음 4장의 켜기·끄기 보기 및 난수 호출 순서 동일, 혼동·중복 표시·듣기 카드 제외와 최대 30회 제한, 실제 목록 전수 표시 고유성/품사 결과 집계를 검사했다.
- `node --test tests/*.test.mjs`: **100/100 통과**, 실패·skip 0(기존 96 + 새 O5~O8 4개). 카드 단위 파일 직접 실행도 62/62이며 기존 O1~O4 통과.
- `node tests/cards_e2e.cjs`: 최종 재실행 **149/149 통과**, page/console error 0. 최초 실행은 번개 라운드 점수·보상 확인 1건이 실패해 148/149였다. 코드·테스트를 수정하지 않고 재실행해 통과했고, 첫 실패의 원인은 확정하지 못했다. Playwright 번들 브라우저가 없어 외부 preload에서 설치된 `/usr/bin/chromium` 경로만 지정했다(재실행은 실패 시 상태 출력용 관찰도 추가). 테스트 파일·검사 조건·대기는 바꾸지 않았다.
