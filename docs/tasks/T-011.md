# T-011 교차 검토(C-005)가 찾은 결함 9건을 고쳐라

- 상태: 진행
- 담당 층: 구현 (Opus)
- 선행 카드: C-005(완료), T-003(완료)
- 브랜치: `t-011-review-fixes` (기준 `claude/modest-mccarthy-3gadjk`. 푸시하지 않는다. 설계 층이 검토 후 병합한다)

## 목표

아이의 진행 기록이 사라지는 경로 네 개와, 복습에 들어갈 수 없게 되는 경로, 규칙과 다르게 동작하는 경로를 실사용 전에 막는다.

## 배경

`docs/reviews/C-005.md`가 결함 9건을 재현 조건과 함께 적었다. 먼저 그 문서를 읽는다. 아래는 결함마다 설계 층이 정한 고치는 방법이다. 이 방법대로 구현하고, 결함마다 보고서의 재현 조건을 그대로 되살린 회귀 검사를 추가한다.

## 고치는 방법

### F1 다른 탭이 저장한 기록을 덮어쓴다 (`cards/js/main.js`, `cards/js/sync.js`)

- 저장 직전에 저장소의 현재 값을 다시 읽는다. 이 화면이 마지막으로 읽거나 쓴 문자열과 다르면 다른 탭이나 동기화가 바꾼 것이다.
  - 그 값의 형식 번호가 이 프로그램보다 높으면: 쓰지 않는다. 읽기 전용으로 바꾸고 "새로 고침" 배너를 띄운다(이미 있는 `NEWER` 문구). 이후 판을 시작할 수 없다.
  - 아니면: 그 값과 메모리의 기록을 `mergeCards`로 합쳐 메모리 기록에 반영한 뒤(진행 중인 판이 같은 객체를 쥐고 있으므로 `onMerged`처럼 제자리에서 바꾼다) 저장한다.
- `storage` 이벤트로도 같은 처리를 한다(다른 탭이 저장한 즉시).
- `Sync`는 이 기기의 기록이 새 형식이면(`v > SCHEMA`) 서버에 올리지 않고 `stale`을 켠다.

### F2 접힌 판 기록과 합칠 때 다른 기기의 판 통계가 빠진다 (`cards/js/store.js`)

- `compact`는 30일보다 오래된 판만 접는다(판 수가 한도를 넘어도 최근 30일 판은 그대로 둔다). `compact(state, today)`로 오늘 날짜를 받는다.
- 남는 한계를 `docs/DATA_SAFETY.md`에 적는다: 한 기기가 30일 넘게 따로 플레이하다 합치면 그 기간의 판 통계(카드 수·시간)가 합계에서 빠질 수 있다. 단어 기록은 빠지지 않는다.

### F3 동기화가 깨진 기록을 보관하기 전에 덮어쓴다 (`cards/js/sync.js`, `cards/js/store.js`)

- `store.js`의 "따로 보관" 부분을 함수로 내보내고(`loadRecord`도 그것을 쓴다), `Sync`가 로컬 값을 읽다 실패하면(JSON이 아니거나 기록 모양이 아님) 먼저 그 함수로 보관한 뒤 "기록 없음"으로 처리한다. `meta` 문서에도 적용한다.

### F4 외부 백업이 올라가지 않았는데 성공으로 표시한다 (`tools/backup_state.sh`)

- "바뀐 것 없음" 경로에서도 `git push`가 성공해야만 성공으로 적는다. 실패하면 실패로 적고 종료 코드 1.

### F5 공개 저장소를 백업 대상으로 막지 못한다 (`tools/backup_state.sh`)

- 올리기 전에 `origin` 주소를 본다.
  - GitHub 주소면 인증 없이 `https://api.github.com/repos/<소유자>/<이름>`의 응답 코드를 확인한다. 200이면 공개 저장소이므로 거부. 404면 비공개로 보고 진행. 그 밖(네트워크 없음, 403 등)이면 "확인할 수 없음"으로 거부한다.
  - 로컬 경로(다른 디스크의 bare 저장소 등)는 진행한다.
  - 그 밖의 호스트는 거부한다.
  - 사용자가 직접 확인했을 때 쓰는 우회: 환경 변수 `CARDS_BACKUP_ASSUME_PRIVATE=1`.
- 검사를 위해 응답 코드를 환경 변수 `CARDS_BACKUP_TEST_HTTP`로 대신 줄 수 있게 한다(실제 네트워크 없이 시험).
- 거부할 때는 파일을 복사하거나 커밋하기 전에 멈춘다.

### F6 남은 복습이 몇 장뿐이면 들어갈 길이 없다 (`cards/js/map.js`, `cards/js/world.js`, `cards/js/main.js`)

- "기다리는 카드"를 센다: 복습(`review`, `likely`)과 배우는 단어(`learn`) 중 날짜가 오늘 이전이고 오늘 채점하지 않은 것.
- 몬스터가 없는데(8장 미만) 기다리는 카드가 1장 이상이면 지도 아래 줄에 "복습 N장" 버튼을 보여 준다. 누르면 복습 판(종류 `review`: 새 단어 없음, 복습 14장까지, 배우는 단어 재도전 포함, 묶음 표본 확인도 섞임)이 시작된다. 별은 보통대로, 아이템은 없다. 박쥐가 가득 차면 다른 칸처럼 막힌다.
- 모든 세계와 성을 마친 뒤에도 이 버튼으로 남은 카드를 볼 수 있어야 한다.

### F7 판을 중간에 나가도 칸이 깨진다 (`cards/js/world.js`, `cards/js/main.js`, `cards/js/sync.js`)

- 칸 판(지도 칸, 집의 칸)을 시작할 때 그 세계 기록에 "진행 중" 표시를 남긴다: `worlds[세계].open[칸 id] = 오늘`.
- 칸 판이 끝까지 간 경우(`reason: 'done'`)에만 그 표시를 지운다. 중간에 나가면 남는다.
- 칸이 "깬 칸"인 조건: 모든 단어에 기록이 있고 **진행 중 표시가 없다.** 지도의 열림 판정(`reach`), 왕관, 칸 수, 끝 화면의 "칸 클리어"가 모두 같은 조건을 쓴다.
- 진행 중인 칸은 지도에서 열린 칸으로 보이고 다시 누를 수 있다. 다시 들어가 판을 끝내면(새로 낼 카드가 없어 바로 끝나더라도) 깨진다.
- 예전 기록에는 표시가 없으므로 지금처럼 단어 기록만으로 판정된다(변환 단계 없음, 형식 번호 그대로).
- 합치기: `open`은 양쪽을 합치되, 어느 한쪽에서 그 칸이 `cleared`에 있으면 표시를 지운다.

### F8 "미정"인 대륙 성을 기본값으로 열어 준다 (`cards/js/world.js`, `cards/js/main.js`)

- 세계 파일의 `finale.status`가 `pending-config`이거나, `finale`가 있는데 `cards`나 `passRate`가 명시적으로 null이면 "준비 중"이다. 세계 지도에 "준비 중이에요"로 보이고, 시작되지 않고, 다음 대륙도 열리지 않는다.
- `finale` 자체가 없거나 값이 들어 있으면 지금처럼 동작한다.

### F9 같은 날 나중에 틀린 답이 합치기에서 사라진다 (`cards/js/deck.js`, `cards/js/sync.js`)

- 단어 기록을 바꿀 때마다 그 시각을 넣는다: `at`(판의 `now()`가 주는 밀리초 정수).
- 합칠 때 두 쪽 모두 `at`이 있으면 `at`이 늦은 쪽이 이긴다. 한쪽이라도 없으면 지금 규칙(날짜, 그다음 진행 등급).
- 형식 번호는 올리지 않는다(덧붙는 선택 필드). 훑기로 넘긴 단어의 기록에도 `at`이 들어간다.

### F10 박쥐 시험 끝 화면의 문구 (`cards/js/main.js`)

- 박쥐 시험을 마쳤는데 미뤄 둔 복습 때문에 박쥐가 또 오는 경우에는 "박쥐 게이지가 0으로 돌아가요"를 보여 주지 않는다.

## 바꾸면 안 되는 것

- 저장 형식 번호(`SCHEMA`는 2 그대로), 저장소 키, 카드 id, 세계 id, `tests/fixtures/saves/*`.
- 복습 간격, 박쥐 게이지 값(`RULES`, `BAT`), 훑기 규칙(`TRIAGE`), 성 규칙.
- 보상이 복습 일정이나 등급을 바꾸게 하지 않는다.
- `tools/serve_cards.py`, `tools/sim_learning.mjs`, `cards/data/*`, `reference/`, `.github/`, `docs/reviews/*`.
- 기존 검사를 지우거나 약하게 하지 않는다. F7 때문에 기대값이 바뀌어야 하는 기존 검사는 고치되, 무엇을 왜 바꿨는지 결과에 적는다.

## 완료 기준

```sh
node --test tests/*.test.mjs     # 전부 통과
node tests/cards_e2e.cjs         # 전부 통과 (필요하면 NODE_PATH=$(npm root -g))
node tools/sim_learning.mjs --set chosen --seeds 2 | head -20   # 오류 없이 돈다
bash -n tools/backup_state.sh    # 문법 통과
```

새 회귀 검사(각 결함의 보고서 재현 조건 그대로):

1. F1 브라우저: 같은 브라우저의 두 탭. 탭 B가 새 형식 기록을 쓴 뒤 탭 A에서 칸을 누르면 판이 시작되지 않고 기록이 그대로다. 탭 B가 같은 형식으로 단어를 더 저장한 뒤 탭 A가 저장하면 두 탭의 단어가 모두 남는다.
2. F1 단위: 로컬 기록이 새 형식이면 `Sync`가 올리지 않는다.
3. F2 단위: 30일 안의 판은 한도를 넘어도 접히지 않는다. 오래된 판은 접히고 합계가 맞는다(기존 D5의 뜻을 유지).
4. F3 단위: 깨진 로컬 값 + 읽을 수 있는 서버 기록으로 `Sync.init()` → 보관 사본 1개, 로컬은 서버 기록.
5. F4·F5: 임시 git 저장소로 스크립트를 실제 실행하는 검사(단위 파일 안에서 `child_process`로). 밀어 올릴 곳이 없는 저장소에서 두 번 실행해도 두 번 다 실패로 기록. `CARDS_BACKUP_TEST_HTTP=200`에 GitHub 주소면 거부하고 아무것도 복사하지 않음. 404면 진행. 000이면 거부. 로컬 경로는 진행.
6. F6 단위·브라우저: 모든 것을 마친 기록에 배우는 단어 3개만 남은 상태에서 "복습 3장" 버튼이 보이고 판이 시작된다. 몬스터가 있을 때는 버튼이 없다.
7. F7 단위·브라우저: 10단어 중 마지막 재학습 확인 한 장을 남기고 나가면 칸이 열린 채이고 다음 칸은 잠겨 있다. 새로 고쳐도 같다. 다시 들어가 끝내면 깨진다. 예전 기록(표시 없음)은 그대로 깬 칸이다. 합치기에서 한쪽이 깬 칸이면 표시가 지워진다.
8. F8 단위: `pending-config`인 대륙 성은 열리지 않고 다음 대륙도 열리지 않는다. 값이 있으면 열린다.
9. F9 단위: 같은 날 먼저 금이 된 기록과 나중에 틀려 `learn`이 된 기록을 어느 순서로 합쳐도 `learn`이 남는다. `at`이 없는 옛 기록끼리는 지금 규칙.
10. F10 브라우저 또는 단위로 문구 조건.
