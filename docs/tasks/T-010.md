# T-010 시험용 세계 파일과 옛 카드 목록이 어디에 쓰이는지 조사하고 역할을 줄여라

- 상태: 대기
- 담당 층: 실행 (Sonnet)
- 선행 카드: C-001(완료), T-009(병합 뒤 시작: 시뮬레이션 출력이 바뀌는지 자동으로 본다)
- 브랜치: `t-010-standin-files` (기준 `claude/modest-mccarthy-3gadjk`. 푸시하지 않는다. 설계 층이 검토 후 병합한다)

## 목표

게임이 실제 세계 파일(`cards/data/worlds.json` + `catalogue.json`) 하나만 믿게 된다. 실제 파일이 없을 때 임시 배정으로 조용히 넘어가 아이 기록이 엉뚱한 칸에 쌓이는 일이 없어진다.

## 배경

- 실제 세계 파일이 생기기 전에 쓰던 임시 파일이 남아 있다: `cards/data/worlds.fixture.json`(임시 세계), `cards/data/catalog.json`(4,610장, 주제·품사 없음), `cards/data/words.json`(60단어 시제품, 어디에서도 읽지 않는 것으로 알고 있음).
- 지금 쓰이는 곳 [verified, 2026-11-16 검색]: `cards/js/main.js`가 `worlds.json`을 못 읽으면 `worlds.fixture.json`으로 넘어간다. `tools/sim_learning.mjs`가 `catalog.json`을 읽는다. `tools/make_cards_data.py`가 두 파일과 `cards/audio/words.tsv`를 만든다. 단위·브라우저 검사는 `cards/data/demo/`만 쓴다.
- 파일 삭제는 사용자 확인이 필요하다. 이 카드는 삭제하지 않는다.

## 할 일

1. 조사: 위 세 파일을 읽는 코드·문서를 전부 찾아 표로 적는다(파일, 줄, 무엇에 쓰는지).
2. `cards/js/main.js`: `worlds.json`을 읽지 못하면 임시 파일로 넘어가지 않고 "열 수 없어요" 화면에 이유를 보여 준다. `?set=demo`는 그대로 동작한다. `G.standIn`과 "세계 파일: 시험용" 문구는 쓸 곳이 없어지면 지운다.
3. `tools/make_cards_data.py`: `worlds.fixture.json`을 더는 만들지 않는다. `catalog.json`과 `words.tsv`는 그대로 만든다(시뮬레이터와 음원 스크립트가 읽는다).
4. 시뮬레이터는 고치지 않는다. `catalog.json`을 `catalogue.json`으로 바꾸면 수치가 어떻게 달라지는지는 설계 층이 따로 본다.
5. 결과에 "삭제해도 되는 파일" 목록을 적는다(읽는 곳이 하나도 없음을 확인한 것만). 삭제는 하지 않는다.

## 고칠 수 있는 파일

- `cards/js/main.js`, `tools/make_cards_data.py`, `tests/cards_e2e.cjs`
- `README.md`·`docs/WORLD_SCHEMA.md`의 해당 문장, `docs/tasks/T-010.md`의 결과, `docs/tasks/BOARD.md`의 상태

## 바꾸면 안 되는 것

- 어떤 파일도 지우지 않는다. `cards/data/*`의 내용, `tools/sim_learning.mjs`, `cards/js/`의 규칙 코드, 저장 형식.
- 기존 검사를 지우거나 약하게 하지 않는다.

## 완료 기준

```sh
node --test tests/*.test.mjs
node tests/cards_e2e.cjs                 # 필요하면 NODE_PATH=$(npm root -g)
node tools/check_sim_baseline.mjs        # 통과(출력이 그대로)
python3 -I tools/make_cards_data.py && git status --short cards/   # catalog.json, words.tsv에 변화 없음
```

새 브라우저 검사: `worlds.json` 요청을 막으면(404) "열 수 없어요" 화면이 뜨고 임시 세계로 열리지 않는다. 그 상태에서 저장소에 아무것도 쓰지 않는다.
