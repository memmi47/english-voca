# C-019 꾸미기 아이템을 한눈에 다르게, 뒤로 갈수록 화려하게, 칸마다 처음 열리는 대륙을 조절

- 상태: 대기
- 담당 층: 설계 (Astra: 아이템 표와 시안) → 사용자 확인 → 구현 (Sol)
- 선행 카드: C-018(같은 꾸미기 화면. 그 브랜치 위에 쌓거나 병합 뒤)
- 브랜치: `codex/item-tiers` (기준 `claude/modest-mccarthy-3gadjk`)

## 목표

모자·가방·옷이 자세히 보지 않아도 서로 달라 보이고, 대륙을 지날수록 더 화려하고 좋은 아이템이 나와 계속 탐험하고 싶게 만든다.

## 배경 (사용자 요청 2026-11-18)

- "꾸미는 아이템들 간의 차별화가 덜 됐다. 모자·가방·의상 모두 자세히 보지 않으면 차이를 모르겠다. 아이템별로 더 눈에 띄는 차이를 만들어야 한다."
- "후반으로 갈수록 더 화려하고 좋은 아이템이 나와야 한다. 아이템별로 첫 해금할 수 있는 대륙을 조절할 수도 있다."
- 지금(C-016): 30개 세계 성마다 하나씩, 모자 10·가방 10·옷 10을 세계 순서대로 돌려 배정. 대부분 같은 윤곽에 색과 작은 무늬만 다르다. 탈것 3(대륙 성), 반려동물 3(익힌 단어 500/1500/3000), 예전 별 선물 6(C-018에서 제 칸으로).

## 1. 등급과 대륙 (설계 층 결정)

| 등급 | 열리는 곳 | 칸 | 그림 기준 |
|---|---|---|---|
| 1 들판 | 대륙 1의 세계 성 8개 | 모자 4, 가방 4 (옷은 아직 없음) | 단순한 윤곽, 2~3색. 그래도 서로 윤곽이 다르다 |
| 2 바다 | 대륙 2의 세계 성 15개 | 모자 4, 가방 4, 옷 7 | 무늬·장식이 붙고 3~4색. 옷은 이 대륙에서 처음 열린다 |
| 3 하늘 | 대륙 3의 세계 성 7개 | 모자 2, 가방 2, 옷 3 | 가장 화려하게: 테두리 장식, 반짝이는 2프레임 움직임(지도와 꾸미기 화면에서), 특별한 윤곽(망토, 긴 깃털 등) |
| 탈것 | 대륙 성 3개 | 3 | 지금 그대로(자전거 → 나룻배 → 열기구). 뒤로 갈수록 크고 화려하게 |
| 반려동물 | 익힌 단어 500 / 1500 / 3000 | 3 | 지금 그대로 |

- 칸별 개수는 위가 기본이다. Astra가 바꾸려면 근거를 적되, "옷은 대륙 2부터", "반짝임은 대륙 3만"은 지킨다.
- 이미 받은 아이템은 다시 잠그지 않는다. 지금 세계 성을 깬 기록으로 계산했을 때 C-016 기준으로 열렸던 아이템 id가 이 표에서 다른 세계로 옮겨 가면, 그 아이는 새 표의 같은 칸·같은 등급 아이템을 받은 것으로 계산한다(결과에 대응표를 적는다). 아이템 id는 그대로 쓰거나, 바꿔야 하면 예전 id → 새 id 대응을 기기별 꾸미기 저장(`cards.v0.look.<아이>`) 읽기에서 옮긴다.
- 꾸미기 화면에서 등급을 테두리 색으로 보여 준다(들판 = 나무색, 바다 = 청록, 하늘 = 금색). 잠긴 아이템은 실루엣(C-018)과 "○○ 대륙에서 열려요".

## 2. 한눈에 다르게: 아이템끼리 지켜야 할 차이

- 같은 칸의 두 아이템은 **윤곽이 달라야 한다.** 색만 다른 아이템은 만들지 않는다(색 바꾸기는 별 색 단계로만).
  - 모자: 챙 넓이, 높이, 꼭대기 장식(방울, 깃털, 뿔, 꽃 등), 모양(챙모자·베레모·고깔·두건·밀짚모자·털모자 …)이 서로 다르다.
  - 가방: 크기와 메는 자리(어깨 가방, 등가방, 허리 주머니, 바구니, 원통 가방, 큰 우편 자루 …)가 서로 다르다.
  - 옷: 길이와 모양(조끼, 긴 외투, 멜빵, 망토, 앞치마, 줄무늬 셔츠 …)과 무늬가 서로 다르다.
- 같은 칸의 두 아이템은 주색(가장 넓은 색)도 서로 뚜렷이 달라야 한다.
- 이 차이를 자동 검사로 확인한다(아래 완료 기준). 기준 수치는 Astra가 정하되, 지도 크기(약 80px)에서 눈으로 구별되는 정도여야 한다.
- 딸의 하트, 아들의 목도리·머리 모양(C-017)은 모든 아이템과 함께 보여야 한다.
- 모두 새로 그린다. 다른 게임의 아이템·캐릭터를 흉내 내지 않는다. 이모지를 그림으로 쓰지 않는다.

## 3. 확인 단계 (구현 전)

1. Astra가 아이템 표(칸, 이름, 등급, 열리는 세계, 윤곽 설명, 주색)와 **시안 한 장**을 만든다. 시안: 칸별로 모든 아이템을 기본 배달부(아들·딸 각각)에게 입힌 그림을 카드 크기와 지도 크기로 나란히. 등급 순서대로.
2. 표와 시안 경로를 PR 설명과 카드 결과에 올리고 **"사용자 확인 대기"로 멈춘다.** 사용자 확인을 받은 뒤 Sol이 나머지를 구현한다.

## 고칠 수 있는 파일

- `cards/js/main.js`, `cards/css/app.css`, 그림 생성기와 그 출력(아이템 전부 다시 그리기 포함)
- `tests/cards_e2e.cjs`, 그림 검사 도구(차이 검사 추가)
- `docs/tasks/C-019.md`의 결과, `docs/tasks/BOARD.md`, `docs/WORKLOG.md` 8절 한 줄

## 바꾸면 안 되는 것

- 규칙 코드(`deck.js`의 `firmCount` 포함), 저장 형식, 아이 기록의 저장 키, 세계·칸 id. 해금은 지금처럼 기록에서 계산한다.
- 이미 열린 아이템을 다시 잠그지 않는다. 보상이 학습에 영향을 주지 않는다.
- 기존 검사를 지우거나 약하게 하지 않는다. `node tools/check_sim_baseline.mjs`의 `--update`는 쓰지 않는다.

## 완료 기준

```sh
node --test tests/*.test.mjs
node tests/cards_e2e.cjs
node tools/check_sim_baseline.mjs      # 그대로
# 그림 검사 도구 통과
```

새 검사(최소):

1. 그림 검사: 같은 칸의 모든 아이템 쌍에서 윤곽(그림이 차지하는 픽셀 모양) 차이와 주색 차이가 정한 기준 이상이다. 기준 값과 가장 비슷한 쌍의 수치를 결과에 적는다.
2. 대륙 1의 성만 깬 기록에서는 옷 칸이 모두 잠겨 있고, 대륙 2 첫 세계 성을 깨면 첫 옷이 열린다.
3. 등급 3 아이템은 반짝임 움직임이 있고, "움직임 줄이기"를 켜면 멈춘다.
4. C-016 기준으로 아이템을 받은 기록(예: 대륙 1의 성 3개)을 넣으면 받은 아이템 수가 줄지 않는다.

화면 캡처(저장소 밖): 시안 한 장, 꾸미기 칸별 화면 세 장(모자·가방·옷), 지도 위 아들·딸이 등급 3 아이템을 입은 모습. 경로를 결과에 적는다.
