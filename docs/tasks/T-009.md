# T-009 규칙이 모르는 사이에 바뀌면 자동 검사가 잡게 하라

- 상태: 대기
- 담당 층: 실행 (Sonnet)
- 선행 카드: T-002(완료), T-006(병합 뒤 시작: 보기 규칙이 난수 순서를 바꿀 수 있다)
- 브랜치: `t-009-rule-baseline` (기준 `claude/modest-mccarthy-3gadjk`. 푸시하지 않는다. 설계 층이 검토 후 병합한다)

## 목표

복습 간격·박쥐 게이지·판 구성 같은 규칙을 누가 실수로 바꾸면 PR의 자동 검사가 실패한다. 일부러 바꾼 경우에는 기준 파일을 같은 PR에서 고치고 이유를 적게 된다.

## 배경

- 시뮬레이터 `tools/sim_learning.mjs`는 게임의 실제 규칙 코드(`cards/js/deck.js`, `map.js`)를 돌린다. 같은 씨앗이면 출력이 글자 하나까지 같다 [verified: T-011 병합 전후 `--set chosen --seeds 5` 출력 동일].
- 지금은 규칙을 건드린 작업마다 설계 층이 손으로 비교한다. 이것을 자동 검사로 옮긴다(`docs/ORCHESTRATION.md` 점검 B).
- 수치의 뜻(54주 등)은 가정에 기댄 추정이다. 이 검사는 "수치가 좋은가"가 아니라 "바뀌었는가"만 본다.

## 만들 것

1. `tools/check_sim_baseline.mjs`: `node tools/sim_learning.mjs --set chosen --seeds 2`를 실행해 표준 출력을 `tests/fixtures/sim/chosen-seeds2.txt`와 비교한다. 다르면 달라진 줄을 최대 20줄 보여 주고 종료 코드 1. `--update`를 주면 파일을 새 출력으로 바꾼다.
2. 기준 파일 `tests/fixtures/sim/chosen-seeds2.txt`(현재 출력).
3. `.github/workflows/tests.yml`에 단계 하나: "Rule baseline (simulation output unchanged)". 단위 검사 다음, 브라우저 설치 앞.
4. `docs/ORCHESTRATION.md` 점검 B에 한 줄: 규칙을 일부러 바꾼 PR은 `--update`로 기준 파일을 고치고 PR 설명에 무엇이 왜 달라졌는지 적는다.

## 고칠 수 있는 파일

- 새 파일 `tools/check_sim_baseline.mjs`, `tests/fixtures/sim/chosen-seeds2.txt`
- `.github/workflows/tests.yml`(단계 하나 추가만), `docs/ORCHESTRATION.md`(한 줄), `docs/tasks/T-009.md`의 결과, `docs/tasks/BOARD.md`의 상태

## 바꾸면 안 되는 것

- `tools/sim_learning.mjs`, `tools/sim_scenarios.mjs`, `cards/js/*`, `tests/fixtures/saves/*`.
- 기존 자동 검사 단계를 지우거나 순서를 바꾸지 않는다.

## 완료 기준

```sh
node tools/check_sim_baseline.mjs            # 통과. 걸린 시간을 결과에 적는다(3분을 넘으면 멈추고 적는다)
node --test tests/*.test.mjs
```

확인 방법(결과에 적는다, 커밋하지 않는다): `cards/js/deck.js`의 `INTERVALS` 한 값을 임시로 바꾸면 검사가 실패하고, 되돌리면 통과한다.
