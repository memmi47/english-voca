# C-008 실제 30개 세계에서 회오리가 얼마나 자주, 얼마나 빨리 오는지 재라

- 상태: 대기
- 담당 층: 실행 (Terra). 막히면 Sol.
- 선행 카드: T-007, T-008 (병합됨)
- 브랜치: `codex/storm-measure` (기준 `claude/modest-mccarthy-3gadjk`)

## 목표

부모가 iPad에서 회오리 빈도를 조정하기 전에, 지금 설정값(`cards/js/storm.js`의 `STORM`: 생성 확률 0.35, 하루 3개, 형태 5개 이상)이 실제 지도에서 어떤 경험을 만드는지 숫자로 안다.

## 배경

- 회오리 규칙: `docs/tasks/T-007.md`의 "규칙" 절과 `cards/js/storm.js`. 판이 끝날 때 조건이 맞으면 확률로 생기고, 배달부에게서 길로 가장 먼 칸에 나타나, 판마다 한 칸씩 다가온다.
- 검사는 시험용 세트(`cards/data/demo/`)로만 했다. 실제 `cards/data/worlds.json`(30세계)과 `cards/data/forms.json`에서는 재지 않았다.
- 낼 수 있는 형태 127개 중 104개가 첫 대륙(P1) 단어다 [verified, 2026-11-16].

## 만들 것

1. `tools/measure_storm.mjs`: 실제 규칙 코드(`cards/js/storm.js`, `world.js`, `map.js`, `deck.js`)를 불러 다음을 잰다. 규칙 코드는 고치지 않는다.
   - 세계마다: 칸 수, 배달부가 각 칸에 있을 때 회오리가 생기는 칸까지의 길 거리(최소·중앙·최대). 거리 = 회오리가 생긴 뒤 잡힐 때까지의 판 수.
   - 세계를 앞에서부터 차례로 깨 나갈 때(칸을 지도 순서대로 끝까지 마침, 모든 단어에 기록이 생김), 낼 수 있는 형태 수가 처음 5개 이상이 되는 세계와 칸. 세계별 누적 형태 수.
   - 씨앗 여러 개(최소 200)로 "칸 판을 계속 끝내는 아이"를 돌려: 하루 판 수를 6·12·20으로 둘 때 하루 평균 생기는 회오리 수, 잡히는 수, 회오리 판으로 나가는 카드 수. 회오리 판은 모두 끝까지 푼다고 가정한다.
   - 같은 측정을 `STORM.chance` 0.2와 0.5로도 돌린다(설정값만 바꿔서, 파일은 고치지 않는다).
2. `docs/research/storm_frequency.md`: 위 수치를 표로. 숫자마다 어떻게 셌는지 한 줄. 가정(아이가 칸을 순서대로 깸, 박쥐·몬스터 판은 세지 않음 등)을 맨 위에 적는다. 추천 값은 적어도 되지만 결정은 사용자가 한다.
