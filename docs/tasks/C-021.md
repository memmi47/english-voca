# C-021 비슷해 보이는 꾸미기 아이템, 특히 모자를 한눈에 다르게

- 상태: 대기
- 담당 층: 설계 (Astra: 모양 안과 시안) → 사용자 확인 → 구현 (Sol)
- 선행 카드: C-019(병합됨)
- 브랜치: `codex/item-shapes` (기준 `claude/modest-mccarthy-3gadjk`)

## 목표

모자·가방·옷이 지도 크기(배달부 약 80px)에서도 서로 다르게 보인다. 특히 모자는 윤곽(높이와 모양)만 봐도 무엇인지 안다.

## 배경

- 사용자(2026-11-18): "아이템 몇 가지는 비주얼이 너무 비슷해서 차별화가 필요하다. 모자가 특히 비슷하게 보이는 경우가 많다."
- Claude가 꾸미기 화면에서 본 것 [verified: 화면 캡처 2026-11-18]: 밀짚 우편모자, 조개 두건, 파도 챙캡, 잎사귀 모자(별 선물)가 모두 낮고 납작한 윤곽이라 색 말고는 구별이 어렵다. 밤하늘 모자도 낮은 덩어리 모양이다. 솔방울 고깔과 석양 깃관은 높이가 있어 구별된다.
- C-019는 같은 칸끼리 윤곽 차이 검사를 넣었지만, 겹치는 면적 비율(1−IoU)만 보므로 "둘 다 낮고 납작한" 모자들이 기준을 넘었다. 높이·폭 같은 모양 특징으로도 구별되어야 한다.

## 정할 것 (설계 층 결정)

1. 모자 7개(세계 성 5 + 별 선물 2)는 서로 다른 **모양 종류**에 하나씩만 속한다: 넓은 챙모자, 높은 고깔, 둥근 털모자(방울), 두건(머리와 귀를 덮음), 챙이 앞으로만 있는 모자, 높은 원통 모자, 장식 관(깃털·볏) 등. 같은 종류 두 개는 안 된다.
2. 지도 크기 기준으로 모자들의 높이(배달부 머리 위로 솟은 픽셀 수)와 폭이 서로 달라야 한다. 높이가 2px 이하로 비슷한 두 모자는 폭이 4px 이상 다르거나 꼭대기 장식이 달라야 한다.
3. 가방과 옷도 같은 기준으로 다시 본다: 가방은 메는 자리(어깨·등·허리·손)와 크기, 옷은 길이(짧은 조끼·긴 외투·망토)와 실루엣이 달라야 한다. 비슷한 쌍이 있으면 고친다.
4. 색은 같은 칸끼리 주색이 겹치지 않게(C-019 기준 유지). 딸의 하트, 아들의 목도리·머리 모양은 모든 모자와 함께 보여야 한다.
5. 아이템 id·이름·여는 조건·등급은 바꾸지 않는다. 그림(모양)만 바꾼다. 이름이 모양과 맞지 않게 되면 이름을 바꾸지 말고 모양을 이름에 맞춘다.

## 확인 단계 (구현 전)

Astra가 시안 한 장을 만든다: 칸별로 모든 아이템을 아들·딸에게 입힌 그림을 카드 크기와 지도 크기(80px)로 나란히, 그리고 모자만 따로 실루엣(검은색으로 채운 윤곽)으로 한 줄. 경로를 PR 설명과 카드 결과에 올리고 **"사용자 확인 대기"로 멈춘다.** 사용자가 Codex 채팅에서 확인하면 구현한다.

## 고칠 수 있는 파일

- 그림 생성기와 그 출력(꾸미기 아이템 그림)
- 그림 검사 도구(모양 특징 검사 추가: 같은 칸 아이템 쌍의 높이·폭·윤곽 차이)
- `tests/cards_e2e.cjs`(그림이 바뀌어 기존 검사의 픽셀 기대값이 바뀌면 같은 것을 확인하도록 고치고 결과에 적는다)
- `docs/tasks/C-021.md`의 결과, `docs/tasks/BOARD.md`, `docs/WORKLOG.md` 8절 한 줄

## 바꾸면 안 되는 것

- 규칙 코드, 화면 동작, 저장 형식, 저장 키, 아이템 id·이름·여는 조건.
- 이미 연 아이템을 다시 잠그지 않는다.
- 다른 게임의 아이템을 흉내 내지 않는다. 이모지를 그림으로 쓰지 않는다.
- 기존 검사를 지우거나 약하게 하지 않는다. `node tools/check_sim_baseline.mjs`의 `--update`는 쓰지 않는다.
