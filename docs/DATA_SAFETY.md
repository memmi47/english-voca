# 진행 기록 보호

작성 2026-11-16. 목적: 프로그램을 업데이트하거나 기기·주소가 바뀌어도 아이의 진행 기록이 사라지지 않게 한다. 대상: 부모(설정·복원), 프로그램을 고치는 모든 작업자(지켜야 할 규칙).

## 1. 기록이 있는 곳 (네 군데)

| | 위치 | 언제 쓰이나 | 상태 |
|---|---|---|---|
| ① | 기기의 브라우저 저장소 | 평소 작업본. 서버가 꺼져 있어도 플레이 가능 | 동작 |
| ② | Mac 서버의 `state-cards/` (최신본 + 직전 30개 버전) | 맥미니·iPad 공유, 브라우저 저장소가 지워졌을 때 자동 복구 | 동작 |
| ③ | `state-cards/daily/` 날짜별 사본 (플레이한 날마다 하나, 400일) | 며칠 전 상태가 필요할 때. 부모 화면에서 골라 복원 | 동작 |
| ④ | 비공개 GitHub 저장소 | Mac 디스크 고장·폴더 삭제에 대비한 외부 사본. 과거 버전을 계속 볼 수 있음 | 스크립트 준비됨. **설정 필요** (3절) |

부모 화면 위쪽의 "기록 보관 상태"에 네 군데의 상태가 표시된다. 문제가 있는 곳은 붉은 글씨다. 수동 사본이 필요하면 "기록 내보내기(파일)"로 받는다.

## 2. 업데이트가 기록을 지우지 못하게 하는 장치

| 위험 | 장치 | 검사 |
|---|---|---|
| 저장 형식이 바뀜 | 기록에 형식 번호가 있고, 옛 형식은 읽을 때 새 형식으로 올린다(단어 기록은 손대지 않음) | 단위 D1·D2, 브라우저 10e. 옛 프로그램이 실제로 저장한 파일을 `tests/fixtures/saves/`에 두고 매번 새 코드로 연다 |
| 저장 형식 1 → 2 (칸 훑기 묶음, T-003) | `STEPS`의 1 → 2 단계가 `bunches: {}`만 만든다(단어 기록은 손대지 않음). 넘긴 단어의 `bunch` 필드와 `bunches`는 두 기기를 합칠 때 살아남는다(묶음은 끝난 쪽 우선, 둘 다 끝났으면 이른 날짜, 둘 다 안 끝났으면 이른 기한) | 단위 D1·D9·S11, 브라우저 10e. 형식 2로 저장한 `tests/fixtures/saves/v2-bunches.json` |
| 옛 화면이 새 기록을 덮어씀 (업데이트 중 열려 있던 탭) | 자기보다 새 형식의 기록은 읽기 전용으로만 보여 주고 "새로 고침"을 요청. 서버에도 쓰지 않는다. 화면은 저장하기 직전마다(그리고 다른 탭이 저장한 즉시 `storage` 이벤트로) 저장소의 현재 값을 다시 읽는다: 마지막으로 읽거나 쓴 값과 다르면, 새 형식이면 읽기 전용으로 바꾸고 판을 시작하지 않으며, 같은 형식이면 메모리의 기록과 합친 뒤 저장한다. 이 기기의 기록이 새 형식이면 동기화도 서버에 올리지 않는다(T-011 F1) | 단위 D3·F1, 브라우저 10e·13(F1 두 탭) |
| 저장 도중 끊겨 기록이 깨짐 | 읽을 수 없는 기록은 덮어쓰지 않고 따로 보관(최근 3개)한 뒤 서버 사본으로 이어 간다. 앱 시작 때 동기화가 먼저 읽는 경우에도 같은 함수(`store.setAside`)로 먼저 보관한 뒤 서버 사본을 넣는다. `meta`도 같다(T-011 F3) | 단위 D4·F3, 브라우저 10e |
| 버그가 빈 기록을 서버에 올림 | 서버는 단어 수가 눈에 띄게 줄어드는 저장(10장 이상이던 기록이 90% 미만으로)과 옛 형식의 저장을 거부하고, 거부한 내용은 `rejected/`에 보관 | 단위 D7 |
| 두 기기가 따로 플레이 | 합칠 때 양쪽을 모두 살린다(단어는 더 최근·더 진행된 쪽, 칸·성·도장은 합집합). 단어 기록마다 마지막으로 바뀐 시각 `at`(밀리초)이 있고, 두 쪽 모두 `at`이 있으면 늦은 쪽이 이긴다: 같은 날 나중에 틀린 답이 앞선 금을 이긴다. `at`이 없는 옛 기록은 날짜, 그다음 진행 등급(형식 번호는 그대로 2, T-011 F9). 끝내지 않은 칸 판의 표시(`worlds[세계].open`)는 합집합이되, 어느 쪽에서든 깬 칸이면 지운다(T-011 F7) | 단위 S1~S11·F9·F7(병합) |
| 세계 배정이 바뀜 | 단어 기록은 카드 id 기준이라 그대로 남는다. 열쇠·왕관은 세계 id 기준이므로 세계 id는 바꾸지 않는다(4절 규칙) | 단위 W·D1 |
| 주소가 바뀜 (포트, 로컬 → 클라우드) | 브라우저 저장소는 주소마다 따로다. 새 주소로 처음 열면 서버 사본을 자동으로 불러온다. 서버를 옮길 때는 `state-cards/` 폴더를 함께 옮긴다 | 브라우저 11("지워진 브라우저가 서버에서 되찾음") |
| 기록이 계속 커져 브라우저 저장 한도를 넘음 | 판이 500판을 넘으면 오래된 판 기록을 합계로 접는다(최근 300판은 그대로). 합계 수치는 유지. 최근 30일의 판은 한도를 넘어도 접지 않는다(`compact(state, today)`, T-011 F2). **남는 한계:** 한 기기가 30일 넘게 따로 플레이하다 합치면, 다른 기기가 이미 접은 기간에 든 그 기기의 판 통계(카드 수·시간 등)가 합계에서 빠질 수 있다. 단어 기록은 빠지지 않는다 | 단위 D5·F2 |
| iPad Safari가 저장소를 비움 | Safari는 7일 동안 그 사이트를 쓰지 않으면 저장소를 지울 수 있다. 홈 화면에 추가한 웹앱은 예외다 [verified: WebKit 정책 설명 기사, 4·5번 출처. 최신 iPadOS에서의 동작은 직접 확인하지 못함]. 서버 사본이 있으면 다음 접속 때 자동 복구된다 | iPad에서 "홈 화면에 추가" 권장 |

## 3. 부모가 할 일

1. iPad에서 게임을 연 뒤 공유 버튼 → "홈 화면에 추가". 이후 그 아이콘으로 실행한다.
2. 외부 백업(④) 설정. 게임 저장소(`memmi47/english-voca`)는 **공개** 저장소라 기록을 올릴 수 없다. 기록에는 아이 이름과 학습 내용이 들어 있으므로 별도의 비공개 저장소가 필요하다.
   - GitHub에서 비공개 저장소를 하나 만든다(예: `english-voca-state`, Private).
   - Mac에서 한 번: `git clone <그 저장소 주소> ~/english-voca-state`
   - 시험: `bash tools/backup_state.sh ~/english-voca-state` → "백업 완료"가 나오고 부모 화면의 ④가 날짜로 바뀌면 된다.
   - 매일 자동 실행(선택): `crontab -e`에 한 줄 `0 21 * * * CARDS_BACKUP_REPO=$HOME/english-voca-state /bin/bash <게임 폴더>/tools/backup_state.sh >> $HOME/english-voca-backup.log 2>&1`
   - 3일 넘게 백업이 안 되면 부모 화면의 ④가 붉게 표시된다.
   - 스크립트는 복사하기 전에 올릴 곳(`origin`)을 확인한다. GitHub 주소면 로그인 없이 `api.github.com`에 물어 공개 저장소(응답 200)는 거부하고, 비공개(404)만 쓴다. 응답이 없거나 그 밖의 값이면 "확인할 수 없음"으로 거부한다. 이 Mac의 폴더(다른 디스크의 bare 저장소 등)는 쓰고, 그 밖의 호스트는 거부한다. 저장소 설정을 직접 확인했다면 `CARDS_BACKUP_ASSUME_PRIVATE=1`로 이 확인을 건너뛸 수 있다(T-011 F5).
   - "백업 완료"·"변경 없음"은 `git push`가 성공했을 때만 기록된다. 바뀐 것이 없어도 올리지 못하면 실패로 기록하고 종료 코드 1로 끝난다(T-011 F4).
3. 프로그램을 업데이트(`git pull`)할 때는 아무것도 하지 않아도 된다. `state-cards/`는 저장소가 관리하지 않는 폴더라 업데이트가 건드리지 않는다. 다만 게임 폴더를 통째로 지우고 다시 받으면 `state-cards/`도 지워진다. 이를 피하려면 서버를 `CARDS_STATE_DIR=~/english-voca-data python3 tools/serve_cards.py`처럼 게임 폴더 밖의 폴더로 실행한다(백업 스크립트에도 같은 값을 준다).

복원 방법 (부모 화면)

| 상황 | 방법 |
|---|---|
| 기기를 바꿨다, 브라우저 기록이 지워졌다 | 아무것도 안 해도 된다. 서버에 연결되면 자동으로 불러온다 |
| 며칠 전 기록으로 채우고 싶다 | 아이 이름 아래 "날짜별 사본"에서 날짜를 고르고 "그 날짜 사본에서 복원" |
| 서버 기록까지 없어졌다 | GitHub 백업 저장소에서 `state-cards/p.son.json`을 내려받아 "파일에서 복원" |
| 내보내 둔 파일이 있다 | "파일에서 복원" |

복원은 모두 "합치기"다. 지금 기록과 사본 중 더 진행된 쪽이 남고 어느 쪽도 지워지지 않는다. 그래서 일부러 과거로 되돌리는 용도(진도를 낮추기)로는 쓸 수 없다.

## 4. 작업자 규칙 (어느 모델이든)

1. 저장 형식을 바꾸면 `cards/js/deck.js`의 `SCHEMA`를 올리고 `cards/js/store.js`의 `STEPS`에 변환 한 단계를 추가한다. 변환은 단어 기록을 지우지 않는다.
2. 형식을 바꾸기 전 프로그램이 저장한 파일 하나를 `tests/fixtures/saves/`에 추가한다. 그 폴더의 파일은 고치거나 지우지 않는다.
3. 저장소 키(`cards.v0.p.son` 등)와 카드 id, 세계 id는 바꾸지 않는다. 키의 `v0`은 이름의 일부이지 버전이 아니다.
4. 기록을 빈 값으로 만드는 코드를 넣지 않는다. 초기화가 필요하면 부모가 누르는 버튼으로만 하고, 서버 사본은 남긴다.
5. `tests/cards_safety.test.mjs`와 브라우저 테스트 10e·11이 통과하지 않으면 병합하지 않는다.

## 5. 확인하지 못한 것

- iPad 실기기에서의 저장·복원 전부, 홈 화면 웹앱의 저장소 유지.
- macOS에서의 `backup_state.sh` 실행과 cron 등록(리눅스에서 임시 git 저장소로 올리기·변경 없음·게임 저장소 거부·오류 표시를 확인함). T-011 이후 단위 F4·F5가 스크립트를 임시 git 저장소로 실제 실행한다: 올릴 수 없는 저장소에서 두 번 실행해도 두 번 다 실패, GitHub 주소에 응답 200·000·403이면 복사 전에 거부, 404·로컬 폴더면 올림. GitHub API에 실제로 묻는 경로(`curl`)와 실제 GitHub 비공개 저장소로의 올리기는 시험하지 않았다(응답 코드는 `CARDS_BACKUP_TEST_HTTP`로 대신 줌). 스크립트는 bash 3.2에 없는 기능(연관 배열, `mapfile`)을 쓰지 않지만 macOS에서 직접 돌려 보지는 않았다.
- GitHub 인증: Mac에 이미 설정된 git 인증을 그대로 쓴다. 이 프로그램은 토큰이나 비밀번호를 저장하지 않는다.
