# 테스트 보고 (2026-11-11)

환경: Linux 컨테이너, Node 22, Python 3.13, Chromium(Playwright). 서버 `tools/serve.py`. iPad/Safari 실기기 없음.

## QA 검수 결과 처리 (docs/research/qa_review.md)

재현 후 수정(회귀 테스트로 고정): 도입만 되고 채점 안 된 카드 유실, 데모 가져오기가 실제 카드를 덮어쓰고 데모 삭제 시 실제 진도 삭제, 그림 문항 보기 1~2개, 빈칸에서 같은 단어 두 번째 노출, 같은 날 depth 1 오답 후 depth 2 정답의 streak 증가, 소리 확인 전 채점, 가져오기 검증(book/tier/카탈로그 밖 카드/local_cards 형식/`__proto__` 계열 ID), 손상된 저장소 JSON 백업, 날짜 고정(자정 경과), 세션 중 시간 저장, 철자 힌트 중복 글자, 피드백 후 건너뛰기의 이중 기록, 설정 범위, 세션 `sample` 오표기.

수정하지 않음(경미, 의도적 보류): 복귀 안내 문구의 화면별 공백, 늦게 도착한 재생 실패의 문항 귀속 가능성, 저장 실패 배너가 다음 재생 성공 때 가려지는 문제, `?today`·`?speed`·`window.__cu` 테스트 훅이 운영 빌드에도 열려 있음(가족 내부 사용 가정).

## 미테스트

- iPad Safari/iPadOS 실기기: 최초 재생, 빠른 화면 전환, 잠금 후 복귀, 무음 스위치, 블루투스. Chromium 결과는 Safari를 대체하지 못한다. `audioSession` 설정과 "해제된 audio 요소의 src 교체는 제스처 불필요"라는 가정은 실기기 확인 전까지 가설이다.
- 개발용 합성 음원의 실제 발음 품질, 동형이의어 음원의 정확성(데모에는 wind 명사형 1건만 사용).
- 사람이 검수한 음원의 승인 → 교체 → 해제 절차의 종단 실행(도구는 구현, 실제 승인 기록 없음).
- 실제 학원 책 표본, 실제 주간 도구 export 파일(데모 팩은 같은 형식을 따라 만든 자작).
- WebKit, Firefox. Mac Safari. 5~10분 이상의 장시간 사용, 저장소 용량.
- 서버 보관 사본의 실제 Mac ↔ iPad 사용(같은 Wi-Fi, 실기기). Safari의 localStorage 삭제가 현재 iPadOS에서 실제로 일어나는 조건. 앱 전환 후 복귀 시 자동 재생 시도가 iPad에서 허용되는지.
- 한 아이가 두 기기에서 동시에 진행하는 경우의 화면 동작(병합 규칙만 단위 테스트).
- 15분 종료의 실제 시계 시간 경과(가상 시간으로만 확인).
- 그림 선택지가 아이에게 명확한지(예: shadow와 crept 그림이 모두 사람 형상). 아이 사용 관찰 없음.
